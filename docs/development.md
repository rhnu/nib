# nib 开发说明

产品概念与目标行为见[设计说明](design.md)，当前可用能力及最短启动方式见 [README](../README.md)。本说明记录工程入口和需要跨模块保持的约束。

## 工程边界

Cargo workspace 包含三个包：`nib-app` 是不依赖 Tauri 的应用库；`nib-desktop` 是桌面宿主；`xtask` 负责开发工具。React 前端与宿主位于同一桌面应用目录，pnpm workspace 管理前端依赖。

依赖方向为桌面宿主 → 应用库 → bridge；xtask 仅依赖应用库的类型生成能力，不依赖桌面宿主。`api` 定义工作台初始响应和 IPC 错误；资源、组合及当前创作的通信类型由所属领域拥有，业务内部不逐层重建等价 DTO。

应用库按以下职责组织。`prompt`、`library` 和 `session` 支撑资源与当前创作；`jobs`、`media` 和 `settings` 支撑 NAI 操作、媒体与宿主账户契约：

| 模块       | 拥有的职责                                                       |
| ---------- | ---------------------------------------------------------------- |
| `prompt`   | Chunk / Preset、实例、作用域、组合解析与来源解释。               |
| `library`  | 资源组织、查找、关系、导入导出与复用入口。                       |
| `session`  | 当前创作、参考输入、Prompt 与图像编辑状态。                      |
| `jobs`     | 付费图像操作的提交、调度、批次和任务状态，直接使用 bridge 执行。 |
| `media`    | 媒体读写、最终结果、来源关系和结果复用。                         |
| `settings` | 账户选择、应用偏好及配置语义。                                   |

查询契约由相应领域拥有。资源搜索、结果查询、词库补全和远程作品发现不统一成“关键字输入、任意 JSON 输出”。同类多来源查询在所属模块中组合，保留来源标识及专有信息；可查询不意味着可写入。

模块默认是源码组织单位，不机械拆为 crate。只有真实的编译依赖、复用或发布需求才增加包边界。Rust 源码使用同名文件和子目录，避免 `mod.rs`；纯逻辑单元测试放在被测模块的独立 `tests.rs` 中。

## 语义、抽象与装配

### bridge 的职责

NAI 模型与参数、校验和归一化、请求准备、图像输入处理、Token、费用、协议执行及流式协议语义属于 `novelai-bridge`。通用 NAI 能力缺口优先在 bridge 中解决。

nib 直接使用 SDK 的公开类型和方法，不创建同义的 Model、Request、Result、Validation 或 Client 包装体系。可以将 SDK 对象与任务标识、资源来源、显示信息组合；不复制其内部规则。应用调度与 SDK 请求生命周期分别承担责任。

正式依赖使用 crates.io 发布的 SDK，关闭默认 features，显式开启 `reqwest-transport` 和 `bundled-assets`。请求规划、流式协议和费用观察属于 SDK 核心；宿主使用统一的 `Transport` 契约装配客户端。模型能力查询、参数默认值、请求校验、归一化、准备、费用预估、Token 与执行直接使用 SDK；Preset 的稀疏声明和当前创作覆盖表示应用组合语义，不建立第二套参数合法性规则。锁文件决定具体解析版本，成员通过 workspace 继承依赖。

内核按实际用例接入 SDK，应用身份、来源与生命周期由相应领域拥有：

| 领域               | 接入能力与边界                                                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session` / `jobs` | 文生图、普通与 Max Enhance 图生图、纯补绘及可选局部图生图；角色、精确参考、V3 原图与编码氛围转移；七项 Director、独立放大、含遮罩与种子的氛围转移编码；SSE / MessagePack 流式执行。付费操作冻结输入后进入同一顺序队列。   |
| `prompt`           | 稀疏设置、预设覆盖与来源，包括 legacy UC、透明输出的 alpha 表示和 ZIP / JSON 响应选择；按实际模型的本地 Token 计数与请求级计数；前端统一组件自动查询字面文本计数。                                                        |
| `media`            | PNG / JPEG / WebP 元信息及载体来源、PNG 文本写入；官方氛围转移文件、集合与 PNG 的导入导出、组包、嵌入和缓存选择；图像及氛围转移产物保存与恢复。氛围转移文档完整保存，选定原图或编码时另建资产，不丢弃模型或参数缓存身份。 |

生成、Director、放大与氛围转移编码按真实操作分支直接使用 SDK；共享队列不要求共享无关字段，氛围转移产物也不当作图像。桌面入口与用法见 [README](../README.md)，真实服务验收的剩余范围见[路线图](roadmap.md)。

SDK 客户端与 bundled Tokenizer 由宿主集中装配和共享，本地 Token 计数与账户读取不初始化生成队列。客户端按不可变凭据版本和执行配置使用，任务执行与重试读取冻结身份，不改用当前活动账户。全局 API 基址直接映射 SDK 的 `ClientConfig.image_base_url`，图像操作与账户查询共用，端点随执行设置冻结到任务。传输响应预算、Multipart 与服务端图像缓存由 SDK 提供，宿主负责装配。账户服务在启动、活动凭据或端点变化、请求终态和过期时合并采样；采样身份包含凭据版本与端点，并用代次拒绝失效回包。失败保留同身份的上次成功值和错误状态，前端共用一个账户查询服务，采样修订使估费失效。通信仅保留时间与必要摘要，不透传原始账户响应。费用观察只记录 SDK 估算和请求终态，未知费用保留为空；Max Enhance 几何直接读取 SDK。

### 可替换能力

明确数据使用 struct / enum，纯转换使用普通函数。需要替换的能力由使用它的模块定义小 Trait，数据库、文件或远程后端分别实现。编译期组合使用局部泛型，运行期选择或异构实现按需要使用 trait object，不让后端类型参数贯穿整个应用。

一个后端可以实现多个小 Trait，多个实现可以共享连接或客户端；不能因为共用数据库连接而合并全部业务职责。资源查询与编辑等不同能力应保持区别。

宿主集中选择后端、创建共享依赖并管理生命周期，业务实现分散在所属模块。应用内核是资源、会话与任务之间的协作机制，不是第二套生成内核或包含所有行为的 Runtime。业务模块不通过全局服务定位器查找任意依赖。

跨模块协同动作可设置用例入口，单纯读取无需统一的 Service / Facade 转发链；查询无需绕行 Jobs，媒体读取无需先构造完整创作工作区。

### 持久化与边界表示

SQLite 使用 rusqlite 的 bundled 后端。全局配置与创作数据使用独立数据库，目录布局和迁移用法见 [README](../README.md#设置与存储)。宿主先加载全局设置，再打开数据目录中的 `nib.sqlite3`；尚无当前创作记录时返回空白状态。SQLite `user_version` 标识各自的结构版本，初始化在事务中完成；开发阶段不兼容旧结构，版本不匹配时明确报错，不回退到空库。资源读取、编辑、搜索和当前创作存储采用各自领域的小契约，SQL 实现也放在所属模块；`persistence` 只维护创作数据库连接、结构初始化及共享错误处理。

应用偏好与账户元数据归 `settings`，不依赖创作数据库。宿主持有配置和数据目录独占文件锁；即时迁移由前端先等待材料提交并保存草稿与偏好，未保存资源阻止迁移。宿主停止接收数据写入和领取新任务，等待已发请求连同结果落盘，再取得数据访问独占保护，执行 SQLite checkpoint、同步复制、逐字节比对和只读数据库完整性检查，成功后原子发布新路径。当前进程继续显示旧目录中的数据并保持只读，重启后打开新目录；失败恢复原目录写入及队列调度。复制标记支持同源重试，源数据保留。目标不能是任意已有库，也不能与配置目录重叠或和源目录相互包含。所有数据库、媒体与缩略图写入都经过访问保护；保护必须移入阻塞任务，不能因等待 IPC 的 future 被取消而提前释放。

开发环境由 Tauri 的开发模式标识判断，默认路径从编译期宿主位置定位到仓库根目录的 `.dev/`，不依赖启动工作目录；正式构建使用系统应用数据目录。开发模式可通过 `NIB_DEVELOPMENT_HOME` 指定绝对目录，宿主在该目录下使用独立的 `config/` 和 `data/`；相对路径会被拒绝，正式构建忽略此变量。隔离人工检查时指向新的空目录，不删除或覆盖已有 `.dev`。配置数据库为空时没有活动账户，不会读取其他配置保存的密钥。开发和正式凭据使用不同服务名，具体条目按不可变版本身份区分。应用偏好与存储选择属全局设置，生成参数、角色和参考属可恢复创作。

资源和当前创作的保存以修订号防止旧内容覆盖新内容：零表示尚未保存，成功写入后返回新修订号。当前创作仅保留一份状态，不具有资源身份和名称；资源的身份、名称与修订号分别只有一个存储来源，组合内容采用必要的 JSON 表示。资源搜索当前按名称和类型筛选，名称不承担引用身份。

角色与参考的解析输出身份按实例身份和原始条目身份组成，直接输出也使用独立命名空间。前后端统一编码为 JSON 二元组，不能按分隔符拆解身份或把解析输出身份当成原件身份；编辑与诊断定位仍须回到所属实例和原始条目。当前创作保留角色的编辑坐标，集合定位设置由 SDK 解析；规范化不反向改写编辑值，结果恢复采用冻结时实际生效的坐标和定位方式。

`session::MaskEditorState` 独立于生成输入保存多源图的原生像素笔画、历史游标、应用版本与画布视图；`Draft.vibeEncoder` 独立保存氛围转移编码输入；导演工具与 PNG 文本写入也按工具和源图独立保留，导航页面随当前创作恢复。这些编辑状态不进入 `ResolvedDraft` 或主生成的依赖键，不因笔画、视图或编码表单变化使提示解析、能力查询与主生成估费失效。编码与导演工具提交临时从独立输入构造适用的操作并单独估费，不覆盖当前生成操作。恢复结果或图片元信息保留当前编辑工作态，前端合并尚未写完的最新编辑。遮罩应用先保存 PNG 媒体，再更新操作的媒体身份。

解析与展开在同一资源读取事务内完成。缺失引用、类型不匹配和失效的局部覆盖返回带实例位置的诊断；存储失败仍然是错误，不能伪装成资源缺失。展开配方会同时解除其启用与停用内容的引用，因此停用项的缺失依赖也会阻止展开，避免以后启用时丢失内容。

秘密凭据由 `settings` 的小契约按不可变版本读取，Windows 宿主串行访问系统凭据后端。配置数据库保存账户名称、活动选择和版本关系；更换 Key 新建版本，旧版本仍供冻结任务使用。删除账户先在阻止新提交的保护内检查全部版本是否有未完成任务，存在引用则拒绝并指向任务处理，删除活动账户不会自动选择另一个账户。前端只接收元数据和状态，输入的秘密只用于当次 IPC，不进入持久状态、SQLite、日志或结果记录。原凭据缺失是显式失败；系统凭据错误中的秘密内容不能跨越宿主边界。

生成提交在一致的资源读取中解析，应用层的请求次数为 1–8；每个请求分别由 SDK 准备并确定随机种子，使用共同批次身份一次持久化。单请求样本数及动态范围归 SDK，批次数量不写入 NAI 单请求字段。各任务冻结有效参数、凭据版本、执行配置与媒体身份，再唤醒唯一顺序执行器。生成只保存一份 SDK 参数和必要来源，不重复嵌入媒体字节；Director 与氛围转移编码保留各自适用输入。SDK 准备对象与协议载荷保持瞬时。重试建立关联原任务的新任务，复用原冻结输入、凭据与端点，不改写原终态。输入媒体损坏使对应任务失败，无法保存状态或结果的存储失败才停止队列；重启把未完成任务标为中断，不自动发起请求。

源图、遮罩、参考和最终产物使用同一媒体能力，通过稳定身份和类型区分使用关系；导入保存实际内容，不依赖外部源文件继续存在。媒体先完整写入并同步文件，再提交记录；最终结果、资产和任务完成状态在同一事务内提交，并尊重已经发生的取消。中断可能留下不可见的未引用文件，但不会出现指向未完成写入的可用结果。查询检查文件存在与长度，缺失或截断内容不可打开或恢复。媒体 IPC 按资产身份返回二进制内容，前端按不可变身份与原图/缩略图用途共享 Blob URL，最后一个使用者离开后释放；列表使用可重建的缩略图缓存。读取媒体不必初始化生成执行器，也不开放任意文件路径读取。

生成结果恢复包含对应输入材料和已知的实际样本种子，独立于旧资源定义。图片未记录样本种子时保留未知状态，恢复原提交种子不能承诺精确重现该样本。图片元信息恢复只投影 SDK 已知字段，明确说明缺失材料与角色位置；嵌入氛围转移可另行导入，不把原图内编码全文再复制到元信息表。流式通知采用有界瞬时通道，窗口负责订阅生命周期；中间帧不落库，SDK 确认完整终态后才保存最终输出。

流式订阅以窗口和订阅身份共同管理，旧订阅清理不能终止新订阅；通道落后时刷新持久任务状态。中间帧按任务和样本维护有界内存，等待、预览与最终图片使用同一请求视图；最终媒体解码后才释放相应帧，终态拒绝迟到事件。多样本网格与单样本大图共用结果读取能力。费用观察按 SDK 请求归属于任务，SDK 请求终态与应用结果保存状态分别记录。

桌面 IPC、交互编辑状态和长期文件格式可以各有必要表示。仅在这些真实边界进行转换，不把 SDK 对象图原样当作前端或永久文件格式；也不因此在应用内部另造一层 SDK 隔离体系。

## 桌面通信与编辑状态

桌面命令提供工作台加载、资源查询与编辑、当前创作保存、解析和展开，以及模型能力查询、媒体导入和元信息、凭据与账户快照、估费、任务、结果和流式订阅。宿主负责集中装配、IPC 错误映射与阻塞存储工作的调度，领域逻辑不依赖 Tauri。应用名和版本来自应用信息，默认模型 ID 直接读取 bridge 的默认模型，不在 nib 中维护默认模型常量或模型列表。

Rust 边界类型通过 serde 定义 JSON 命名，通过可选 `typegen` feature 派生 ts-rs 类型。前端引用已生成的声明，不手写平行类型；业务模块不依赖生成文件。

新增前端命令时同时更新宿主 handler、构建命令清单和主窗口 capability；注册 handler 不会自动授予调用权限。模型编辑选项与范围投影 SDK 描述符，严格拒绝返回 SDK 类型化字段位置，前端不解析错误文案来推断字段。

主表单按实际创作操作查询模型选项，独立放大不消费无关的生成输入。HTML 文件拖放需要关闭 Tauri 原生文件拖放拦截；导入只读取用户选定文件并交给媒体能力保存，不开放任意文件路径读取。异步材料导入和操作准备归属发起时的编辑上下文，操作切换或完整恢复后不得再应用旧回包。共享待完成操作必须覆盖媒体读取、派生、引用创建及编辑提交的整个过程；切页、恢复和关闭先等待这些提交，不能在 IPC 返回后、写入编辑状态前提前解除等待。

```sh
pnpm types
pnpm types:check
```

第一条命令更新生成文件；第二条在内存中重新生成并比较，文件缺失或内容漂移时失败，不写源码。生成文件随代码提交，修改边界类型后必须重新生成。类型生成不在单元测试或 Tauri 构建中暗中运行，Oxfmt 不改写生成产物。

加载页区分正在打开、失败和缺少桌面宿主。调用失败可重试，独立浏览器模式不模拟 Rust 响应。

前端以 `app` 负责启动、主题、路由装配和窗口生命周期，`pages` 组合创作、导演工具、画廊、资源库与设置页面，`features` 按工作台、Prompt、资源库、生成划分能力，`shared` 提供宿主调用边界、Query 客户端和产品 UI。工作台控制器集中协调跨领域动作，图像输入内部按操作状态、源图展示、不同操作参数与 SDK 字段反馈组织。只读宿主查询统一使用 TanStack Query，按领域定义查询键与失效范围；查询缓存不拥有可编辑草稿。当前创作与偏好由 Zustand store 独占编辑状态，保存协调器串行写入并合并修订；复杂的当前创作更新使用 Immer，启动查询只用于首次初始化，重新读取不得覆盖已加载的偏好或未保存编辑。付费提交与重试不自动重放。Base UI 处理弹窗、菜单、开关和浮层，Tailwind 与设计变量承担样式，共享组件只做必要薄封装。

导航使用 TanStack Router 的 Hash history，运行时位置由路由拥有；`Draft.activePage` 只作为重启恢复快照，在导航完成后写入，不反向驱动路由。普通导航和历史前进、后退等待材料提交并处理未应用遮罩；已通过同一保护的领域动作直接完成跳转。当前创作、资源编辑会话、结果选择及保存保护位于页面之外，路由卸载页面不会清除它们。资源编辑与筛选通过会话 store 保留，资源关闭与迁移保护直接读取该 store 的 dirty / busy 状态。

页面、画布及操作面板使用 ErrorBoundary 显示渲染失败并允许重试；长寿命编辑与保存协调器位于可恢复边界之外。业务查询、操作及保存错误分别展示，重试显示不重放付费操作。应用根边界提供最终错误信息；事件处理和异步请求仍由其所属操作报告失败。

手写前端源码文件名统一使用 kebab-case，包括组件、Hook、测试和 CSS；组件、类型与函数声明沿用各自的命名约定。`pnpm lint:web` 通过 Oxlint 的 `unicorn/filename-case` 检查 TS/TSX 文件名，CSS 文件名按本约定维护。生成绑定由类型生成器管理，上游字体资产保留原文件名。

`@/` 指向 `apps/desktop/src/`，在 TypeScript 与 Vite 中共同配置，Vitest 复用 Vite 配置。跨模块的导入、重导出及样式引用使用 `@/`；`app`、`pages`、各 `features/<领域>` 和各 `shared/<能力>` 视为模块，同模块可以使用 `./` 或 `../` 相对路径，`features/generation` 的各子目录属于同一模块。

`pnpm lint:web` 在仓库根目录运行，通过 `eslint-plugin-boundaries` 的 `boundaries/dependencies` 与 TypeScript resolver 解析导入目标，再按 `oxlint.config.ts` 中声明的模块根目录判断归属。`app`、`pages`、各 `features/*`、各 `shared/*`、`bindings`、`assets` 分别划定模块，`src` 根目录文件归入口模块。同模块允许相对路径和 alias，跨模块使用 `@/`；新增领域模块和任意深度的子目录自动遵循这些边界，不按目录层级增加规则。检查覆盖可解析的静态导入、类型导入、重导出、字符串形式的动态导入及 TS/TSX 中的样式导入。CSS 文件内的 `@import` 和 `url()` 按开发约定维护。

任务与结果列表使用 Query 分页摘要，完整冻结输入仅在详情、恢复或重试时读取；活动任务独立查询，不受历史分页限制。最近图片区默认限制 20 张，使用全局 1–200 偏好；画廊独立分页浏览图片历史，任务在按批次组织的抽屉中操作。图片查询与氛围转移材料查询按类型区分，不建立第二套结果事实。账户、持久查询与高频流式反馈分别订阅，预览帧不驱动整个编辑工作台更新。二进制媒体继续由按身份与用途共享的 Blob URL 引用计数管理，避免 Query 缓存另存一份媒体字节。

提示词编辑与只读展示共用组件，文本使用内置 Maple Mono 等宽字体；本地计数按文本和实际模型查询并去抖，计数状态通过图标浮层显示。Maple Mono 只决定显示字体，分词器由 SDK 根据实际模型选择，不能混为同一要求。质量、负面预设和 Furry 选项在提示词浮层中编辑；尺寸预设与动态样本范围直接投影 SDK 能力。图片工具采用紧凑纯图标单排覆层，并提供 tooltip 与可访问名称，内部身份不作为常驻标题。

氛围转移原图参考行拥有显式编码、费用及任务状态。`ensure_vibe_encoding` 按真实材料和有效参数查找已有可用编码或未完成任务，必要时才提交新请求；完成后只有原行仍保持相同输入时才应用结果。更换或移除行不删除已完成材料，也不接受迟到结果覆盖。氛围转移结果归材料查询，不进入图片预览、最近图片或画廊。

前端维护当前编辑快照，防抖向 Rust 请求解析，并丢弃过期解析与估费响应；主表单的模型能力与解析文本从同一次资源读取投影，不为文字编辑再启动独立能力查询。SQLite 持久化当前创作。保存协调器串行写入，保存回执只返回修订号并将其合入当前编辑，不用旧快照覆盖保存期间的新修改。结果恢复沿用当前修订号进入同一保存路径。资源搜索读取摘要，定义按当前创作与资源编辑的依赖批量加载；查询结果是只读缓存，资源变更后定向刷新并使解析和费用预估失效，不在缓存中另建可独立修改的资源事实。

资源定义编辑单独保存；当前创作的所有修改自动保存，仅在失败时提供重试。标题栏关闭与系统关闭使用同一原生关闭请求保护：先处理未保存的资源定义和未应用遮罩，再等待材料提交、当前创作及全局设置全部写完；等待期间新增的工作也必须完成，失败则保留窗口与编辑。只有这条流程成功后才能销毁窗口，不能从标题栏直接销毁来绕过保护。保存失败时保留编辑，不能显示“已保存”。主题启动时从 Rust 同步，修改按顺序写回全局配置，前端不另存持久副本。弹窗和菜单使用 Base UI 的焦点与键盘行为。

Tauri 关闭系统窗口装饰，由前端应用层提供标题栏和窗口控制，关闭按钮沿用保存保护流程；权限仅服务主窗口并采用最小授权及 CSP。宿主统一初始化 tracing；应用库只产生事件，不安装全局 subscriber。日志保留必要上下文与错误原因链，不记录凭据、完整请求或媒体内容。详细执行通知与永久结果记录的分离见[数据生命周期](design.md#数据生命周期)。

## 本地化

前端使用 i18next 与 react-i18next；`shared/i18n/locales/en` 和 `zh-cn` 按业务领域维护完整文案，随应用一起打包。英语目录提供键及插值的类型，简体中文目录通过 `satisfies` 保持相同键结构；数量文案采用 `count` 与语言复数形式，富文本整句使用 `Trans`。界面文字、tooltip、可访问名称及应用自定义的原生对话框文字均从目录读取，用户内容、协议值和外部诊断保留原值。

语言偏好属于 `settings::ApplicationPreferences`，取值为 `system`、`en`、`zh-CN`，复用 `PreferencesWriter` 和配置数据库，不另设浏览器持久副本。设置加载前按系统语言初始化，加载后采用已保存选择；`useLanguage` 同步 i18next 与文档 `lang`，跟随系统时响应语言变化。日期和数字通过共享格式函数使用当前界面语言。

组件使用 `useTranslation` 订阅切换；共享 `t` 也可在普通显示函数中按调用时的语言解释文案。模块级显示映射使用键或 getter，不能在初始化时固定翻译；缓存与长期编辑状态保存业务值及原始错误。局部反馈使用 `useMessageState`，需要延迟解释的本地消息使用 `deferMessage`；本地抛错通过 `MessageError` 保留 Error 与调用栈语义。翻译发生在读取或显示时，切换语言不会清空错误或重建编辑状态。

`api::UserMessage` 是 nib 跨 IPC 与持久化记录的消息契约，按语义变体携带字段、身份及调整参数，由前端统一解释。`ApiError` 的错误分类和定位字段独立保留；SDK 与平台详情使用 `external` 原文传递，不通过匹配可读文案推断类别。远端响应及凭据错误继续遵守原有脱敏边界。新增消息须同时更新前端解释及双语目录；修改通信类型后运行 `pnpm types`。

## 工具与检查

Rust、Node 与 pnpm 版本由仓库配置固定，Cargo 与 pnpm 锁文件纳入版本管理。安装依赖使用 `pnpm install --frozen-lockfile`，Cargo 检查使用 `--locked`；不要通过删除锁文件绕过依赖问题。

检查工具需安装 Rusteward 和 rumdl。项目不覆盖 Cargo 的 `dev` 子命令：

```sh
cargo install --git https://github.com/rhnu/rusteward.git --locked rusteward
cargo-dev --version
```

Windows 可通过 `winget install --id rvben.rumdl --exact` 安装 rumdl，再运行 `rumdl --version` 确认。CI 使用官方 Action 安装工具；rumdl 配置由仓库统一维护。参考 [Rusteward](https://github.com/rhnu/rusteward) 与 [rumdl](https://rumdl.dev/)。

| 命令                 | 用途                                               |
| -------------------- | -------------------------------------------------- |
| `pnpm dev`           | 启动桌面应用与 Vite 开发服务。                     |
| `pnpm dev:web`       | 仅启动前端，显示浏览器模式提示。                   |
| `pnpm build:web`     | TypeScript 检查和前端生产构建。                    |
| `pnpm build:desktop` | 构建 Windows 可执行程序，不生成安装包。            |
| `pnpm types`         | 更新 TypeScript 通信类型。                         |
| `pnpm types:check`   | 只读检查生成类型是否一致。                         |
| `pnpm fmt`           | 写入 Rust、前端与 Markdown 格式修复。              |
| `pnpm fmt:check`     | 只读检查格式与 Markdown 规则。                     |
| `pnpm lint`          | Rusteward / Clippy 与 Oxlint 检查。                |
| `pnpm test`          | Rust 单元测试目标和 Vitest 的 Node 测试入口。      |
| `pnpm check`         | 编译、格式、lint、单元测试、类型一致性与前端构建。 |

Rusteward 负责 Rust 格式与 Clippy，Oxfmt 负责前端和工程配置格式，Oxlint 加载 Stylistic 规则维护声明间空行，rumdl 独立负责 Markdown。`oxlint.config.ts` 与 `oxfmt.config.ts` 使用类型化配置，并纳入工具 TypeScript 检查。`pnpm fmt:web` 执行前端自动修复与格式化；import 段后、函数声明前后及类成员之间留一行，普通变量可连续分组，函数重载与实现保持紧邻。箭头函数、函数表达式与 `useCallback` 声明同样按函数处理。修改文档后在收尾时运行 `pnpm docs:fix <本次修改的文件...>`；例如 `pnpm docs:fix README.md docs/roadmap.md`。

Rust 检查顺序为编译 → 格式 → lint → 单元测试。默认只添加纯逻辑单元测试，不为占位模块、常量或源码布局编写测试，不默认引入集成、UI、E2E、性能或快照测试。内存后端用于验证调度与恢复逻辑，单元测试不代表完成了真实服务、交互或数据库恢复验收。

Windows CI 使用同一检查入口及锁文件，再构建不带安装包的桌面程序。CI 不发布产物、不签名、不配置自动更新。工作流文件的存在不代表远程 runner 已运行；本地构建、人工启动观察和远程 CI 的结果在交付中分别报告。
