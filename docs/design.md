# nib 设计说明

本文定义产品概念、语义归属与交互原则。当前可用功能及操作方式见[功能说明](features.md)，工程实现约束见[开发说明](development.md)，尚未完成的扩展与验收见[路线图](roadmap.md)。

## 产品定位

nib 是本地优先、专用于 NovelAI 的桌面创作工作台。图像操作完成创作，Prompt 资源系统积累并复用创作方法，两者共同构成产品核心。

“轻量”指概念明确、同一语义只有一个归属、已有能力直接复用。应用采用模块化单体，职责清晰的模块直接协作；模块、文件和 crate 的数量不是架构质量指标。

## 创作对象

| 概念       | 职责                                                               |
| ---------- | ------------------------------------------------------------------ |
| 片段       | 可复用的提示词内容。                                               |
| 预设       | 组合提示词作用域、片段、角色、参考材料与必要默认设置。             |
| 资源定义   | 资源库中的可复用原件，具有稳定身份、名称和内容。                   |
| 资源实例   | 当前使用中的启停与局部覆盖，不改写原件。                           |
| 当前创作   | 自动保留的工作台状态，组合文本、资源实例、生成设置与图像编辑状态。 |
| 操作       | 用户要完成的工作，例如生成、局部重绘、放大或导演工具处理。         |
| 任务与批次 | 任务是一次已提交操作的调度单位，批次组织多个请求。                 |
| 结果       | 可继续查看与复用的最终输出，附带必要的实际使用信息。               |
| 媒体资产   | 源图、遮罩、参考与最终产物的实际内容载体。                         |
| 资源库     | 资源定义的组织、检索与复用入口。                                   |

这些概念不逐一对应 crate、服务或数据库表。结果与媒体分别表达业务含义和内容载体；历史、画廊与媒体选择器共用结果和媒体事实，不各自建立所有权及来源关系。

## 资源组合

### 定义与实例

资源库保存定义，当前创作保存引用和本次覆盖。调整衣着、光照或风格中的一项，应在实例中表达，无需复制整个原件。资源更新影响后续编辑与解析，不反向修改已提交任务。

名称用于理解和查找，引用依赖稳定身份。引用保留复用关系，展开把当时有效的内容变成独立可编辑内容；两者都是正常工作流。

### 组织、适用范围与封面

资源与文件夹使用稳定 UUID，名称、别名和目录位置均不参与引用。片段与预设共用逻辑目录树，目录路径由父目录关系派生；移动或改名不改变资源身份。别名用于查找同一资源的不同叫法，标签用于跨目录分类。

资源可以声明多个适用模型，未声明表示无限制。这与预设的默认模型设置分别保存。解析先确定最终模型，再检查实际启用的预设和片段；实例覆盖不解除资源的适用限制，停用内容不阻止当前生成。不兼容内容保留并定位诊断，不静默跳过或切换模型。

封面由资源独立持有。从画廊选图只是快捷导入方式，复制后生成独立媒体身份，不保存源结果或源资产引用。源图之后的修改或删除不影响封面；跨用途使用封面时创建独立媒体身份。底层相同字节可以共享内容文件，文件由仍然持有它的资产保留；缩略图缓存仍是可重建派生数据。

### 内容与设置

片段只提供内容，不隐式改变模型、尺寸或采样设置。预设为每项输出明确目标，只声明自己负责的设置，其余继续使用当前创作或 SDK 默认值；预设不承担整张工作台快照的职责。

组合优先于多层继承。提示词与生成参数使用各自的组合语义，顺序、来源及局部覆盖可解释且可撤销，不套用通用 JSON 合并规则。人物、画风和构图属于资源用途，无需分别建立资源系统。

### 解析与模型语义

解析确定本次实际使用的文字、设置、角色与材料，并保留必要来源。资源用途与组合属于 nib；模型能力、NAI 语法、参数合法性及归一化属于 SDK，nib 不维护第二套能力矩阵和校验规则。

编辑原文与提交文本分别保留。nib 扩展在执行前处理，模型语法由 SDK 分析；无法确定的随机语义应明确报告，不能虚构唯一权重。词库与画师通过提示词插入及现有片段 / 预设复用，不另建组合系统。

## 创作与执行

主流程为：**当前创作与资源实例 → 资源解析 → SDK 请求准备 → 任务执行 → 最终结果**。

当前创作隐式维护一份可恢复状态，不命名或切换保存条目；命名复用归资源定义。资源原件采用显式保存。自动保存失败时保留编辑和可见错误，关闭前等待必要写入完成。

资源解析确定内容，SDK 准备与执行 NAI 请求，任务能力决定何时执行及怎样呈现状态，结果能力负责保留与继续使用。操作类型与返回方式分别表达，流式预览属于执行反馈。

任务冻结实际使用内容、媒体、凭据与执行配置；后续编辑不改变任务。重试创建关联原任务的新任务，保留原终态。请求估算、账户采样、服务终态和本地保存状态分别表达，不能据此推断实际扣费。

材料选择和编辑不隐式发起付费操作。精确参考、氛围转移原图、编码与交换文档保留各自用途及身份；材料不适用时说明原因并保留编辑值。缺少原图的编码不能被当作可重建的原图。

源图、遮罩与参考共享媒体能力。已应用遮罩和未应用画布编辑分别保存，任务只引用已应用材料。恢复结果使用冻结信息，不依赖旧版资源定义仍然存在；恢复生成内容与恢复历史资源结构是不同能力。

## 交互原则

### 上下文菜单

应用 WebView 统一禁用默认右键菜单。文本编辑、资源条目、文件夹、目录空白与独立图片分别提供所属操作，没有适用动作的区域不显示菜单。文本编辑区域优先于包含它的资源菜单；资源卡片中的封面属于资源条目，独立画布与画廊图片属于图片操作。

右击已有选择中的条目保留多选，右击其他条目先切换目标。菜单、三点入口与快捷键使用相同动作和可用条件，破坏性操作仍需确认。键盘可以打开和关闭菜单，Escape 关闭后焦点返回原上下文；文本编辑保留选区与撤销历史。

### 信息结构与布局

页面围绕创作任务组织，新增能力进入相关上下文，不把每个后端模块映射成页面。资源管理页负责原件整理和编辑；工作台通过统一选择弹窗引用资源，保持当前编辑上下文。导演工具保留独立输入，结果上的图像操作紧贴所选图片。

创作采用左侧输入与底部生成区域、右侧共用画布及结果的布局。底部按余额、核心参数摘要和生成按钮排列；参数设置向上展开时隐藏余额，生成按钮始终保留。当前请求的等待、流式预览和最终图片在同一位置呈现，历史图片与任务保留各自查看上下文；源图、遮罩与角色定位沿用主区。具体页面与控件用法见[功能说明](features.md#工作台与当前创作)。

界面保持扁平紧凑，使用黑白双主题与青绿重点色。常规控件高约 30px，主要生成按钮约 40px，细边框和约 4px 圆角配合分组间距，避免多层卡片。侧栏参考宽度为 340–390px；[工作台视觉参考](images/workbench-reference.png)说明基础形态，可用操作以功能说明为准。

页面主体、画布与内容预览统一使用 `--bg` 底色，暗色为 `#1b1d21`，浅色为白色；标题栏与控制面板使用 `--surface`，浮层使用 `--raised`，输入控件使用 `--input`。页面不自行指定另一套整体底色，模块样式只管理所属区域。设置直接显示分类导航和当前分类内容，不重复增加页面标题栏。

设置以分组标题、条目标签和说明形成稳定层次，说明紧随所属标签，控件按内容采用有限宽度并在空间不足时换行。各页面共用标题、字段、选择控件和确认操作的密度与间距，长名称允许换行或截断，具体实现约束见[开发说明](development.md#桌面通信与编辑状态)。

标题栏保留窗口拖动、双击最大化或还原及窗口控制，不放命名草稿标签、自动保存状态或副标题。

应用图标采用黑白粗线轮廓笔尖，标题栏与启动页按主题反色显示。顶部导航保留图标与名称：图像生成使用魔法棒、导演工具使用场记板、画廊使用叠放图片、探索使用指南针、资源使用叠层、词库使用打开的书、设置使用齿轮。导航图标复用 Lucide，采用 24px 网格、20px 显示尺寸与默认描边，选中页通过中性底色和下划线区分。桌面窗口最小尺寸为 1280×720 逻辑像素。

资源管理采用目录树、浏览区与可关闭检查器的布局，网格与详细列表共用选择、筛选及操作。原件编辑使用足够宽的编辑区域，保存与未保存状态直接可见。[资源管理视觉参考](images/resource-library-reference.png)用于说明区域比例，示例文字与资源不构成数据规格。

资源选择弹窗共用资源管理页的目录、网格 / 详细列表与筛选表示，默认采用网格。主提示词、角色提示词和预设入口分别限定资源类型并显示插入目标；选择后就地插入，不经过管理页。弹窗的目录导航只负责浏览，标题与确认底栏固定，目录和结果区分别占满剩余高度并滚动。取消不改写当前创作，插入成功后返回原编辑位置并提供通知。[资源选择视觉参考](images/resource-picker-reference.png)说明弹窗结构。

### 操作与反馈

图片操作使用紧凑纯图标单排覆层，名称由 tooltip 和可访问标签提供；参数使用紧凑网格或浮层，不常驻内部身份。常用设置直接可见，低频设置按需展开，折叠不改写值；字段错误展开并定位对应区域。

帮助在字段旁按需显示，支持悬浮、键盘与点击。错误、资源未保存、替换范围及取消费用风险等影响决策的信息直接可见。估费与提交使用相同操作及输入，未知信息保留未知状态。普通编辑刷新期间可保留同一模型上下文的上次统计，并标记正在更新；执行校验只使用匹配当前输入的结果。高亮与候选展示可在更新时暂时保留，诊断与补全插入只使用最新分析。

短暂操作反馈采用统一浮层通知，不通过增删内容推动布局。任务通知按批次汇总，前台使用应用内通知，后台使用系统通知；生成页和导演工具分别锁定提交入口至所属批次结束，共用工作状态。

切页、折叠和只读查看保留编辑与浏览上下文。替换输入或恢复内容前说明影响范围，异步结果不能覆盖后续选择。窄窗口按阅读顺序重排，长名称允许换行或滚动；浮层限制在视口内，保留关闭、焦点与键盘路径。

语言属于全局偏好，切换只改变界面表达及日期数字格式，不改写提示词、用户命名、路径和媒体内容，也不清空编辑或任务。

### 图像安全与标签

安全检查属于本地图像分析，生成请求和图片保留不依赖模型可用。最终图像按全局自动检查选项评分；主模型未安装、检查关闭或推理失败时保留未知状态和原因，已有有效评估继续保留。图片内容相同的资产共享评估证据，模型和策略版本随证据记录。

安全评分使用固定版本的 anime_dbrating 主模型、WD Swinv2 Tagger v3 临界分数复核和 logistic 级联策略。模型安装与自动检查、WD 复核和展示模糊分别管理；标签提取由用户主动触发，可以独立于自动检查使用。

未知图像正常展示。NSFW 模糊由全局偏好控制，主动打开的大图详情默认豁免，也可设置为继续模糊。临时显示只作用于当前查看器，切换图片或重新打开后恢复；首次点击不同时执行图片原有操作。标签识别保留普通与角色类别、置信度和模型来源，用户筛选并确认后才写入指定提示词。

## 数据生命周期

| 类别               | 示例                               | 保留原则                                 |
| ------------------ | ---------------------------------- | ---------------------------------------- |
| 用户创作数据       | 片段、预设、当前创作与参考材料     | 长期保留，支持复用。                     |
| 最终结果与必要记录 | 最终图片、实际使用内容、参数与来源 | 支持解释、恢复与重新提交。               |
| 可重建派生数据     | 缩略图、搜索索引                   | 可清理，不建立新的资产所有权。           |
| 瞬时执行数据       | 中间帧、进度、准备对象和临时解析   | 仅执行期间存在，不进入永久记录。         |
| 可下载资源         | 词库、语义索引与模型               | 独立安装，可重新获取，不随创作数据迁移。 |

每个图像样本只保留最终版本，用户主动多次生成或修补产生各自结果。氛围转移编码是有复用价值的最终材料，不能仅因可再次计算就视为可随意删除的缓存。

结果只保存足以解释和复用的一份有效信息，不逐层归档编辑请求、领域请求、归一化请求、准备对象与协议载荷。执行通知和永久保存分别处理，事件系统不成为第二份数据来源。

结构化信息使用 SQLite，媒体通过所属能力读写。应用偏好和账户配置全局保存，秘密凭据由系统凭据后端持有。数据目录只决定创作数据库与媒体的位置，不建立可新建、打开或切换的工作区。迁移与清理必须保留原始创作数据及仍被引用的材料；下载资源与创作数据分别管理。

## 在线探索

探索是远程作品的只读发现与创作复用入口，路由为 `/explore`。来源共享搜索、详情、媒体读取及显式导入操作，保留各自查询和详情类型，不要求不同服务具有相同账户、分级、排序或生成元信息。作品身份由来源与远端身份组成，连接修订只约束瞬时请求和缓存，不成为永久作品来源的一部分。

浏览缓存不创建媒体资产或生成结果。用户选择材料用途后，实际图片通过现有媒体能力验证和持久化，并记录远端来源。标签追加与生成内容替换分别表达，替换先展示预览和缺失材料；远程元信息只提供描述，生成合法性仍由 SDK 判断。

NovelAI Explore 的网站协议和元信息适配属于 nib，独立于生成 SDK 与生成凭据。Danbooru 只保留一份可选连接；底层秘密存储共用，账户选择与版本生命周期由各服务需要决定。生成任务仍冻结 NovelAI 凭据版本。

## Agent 创作助手

Agent 理解创作要求，通过既有提示词、资源库、词库及模型描述能力读取和修改内容。它共享当前创作与资源定义，不建立另一份工作台或生成器。模型解释创作意图，提示词语法、参数合法性及归一化继续由 SDK 判断。

接管前停止新的用户编辑并等待已提交输入和自动保存完成，随后取得后端的独占编辑能力。接管期间相关编辑保持只读，对话和停止操作继续可用；完成、取消或失败后先同步最终状态再恢复编辑。后端在同一编辑入口核对所有权与编辑代次，迟到的用户保存不能覆盖 Agent 已提交的内容。取消保留已完成修改，当前创作按一次接管形成撤销组。

本次创作的改变优先使用实例覆盖；修改资源原件需要明确的用户意图。工具保留节点、角色、实例和资源身份及来源，不通过任意 JSON 路径改写数据。资源保存与当前创作分别提交，界面按实际结果报告部分成功。Agent 不持有付费提交工具，用户仍通过生成入口显式提交。

云端连接与 NovelAI 图像账户分别配置，秘密保存在系统凭据后端。发送给模型的内容包括用户消息、当前创作及工具读取的相关资源；对话属于本地创作数据，清空对话不删除已提交的创作或资源。重启不恢复执行尚未完成的工具。

## 扩展边界

应用核心由资源组合、当前创作、SDK 接入、任务、结果及所属存储查询构成。新增 NAI 操作按真实需求接入，SDK 缺口优先在 SDK 解决；未实现模块不预建空壳服务。

在线发现、本地分析、复杂批量策略和资源分发按所属能力扩展；同类来源在所属查询中组合，保留来源与可写边界。

接口随真实用途收敛，不为未知需求预建万能插件、工作流或多供应商框架。公开参数、嵌套组合、集合与资源携带等未完成工作只在[路线图](roadmap.md)维护。
