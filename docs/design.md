# nib 设计说明

本文定义产品与架构基线。当前可用能力见 [README](../README.md)，工程实现约束见[开发说明](development.md)。

## 产品定位

nib 是本地优先、专用于 NovelAI 的桌面创作工作台。原生图像操作完成创作，Prompt 资源系统沉淀并复用创作方法；两者共同构成初版产品，Chunk 和 Preset 不作为基础生成器完成后才补充的管理功能。

“轻量”指核心概念明确、同一语义只有一个归属、已有能力直接复用、外围能力逐步接入。应用采用模块化单体，模块通过清晰的公开能力直接协作。模块、文件和 crate 的数量不是架构质量指标；职责不同或确有替换需求时才增加边界。

## 创作对象

| 概念         | 职责                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| Chunk        | 可复用的提示词内容；从纯文本开始，按需要增加少量公开参数。                 |
| Preset       | 组合片段、提示词作用域、参考材料和必要默认参数的创作配方。                 |
| 资源定义     | 资源库中的可复用原件，具有稳定身份、内容与组织信息。                       |
| 资源实例     | 一次使用定义的方式，保存本次参数、启用状态与局部覆盖，不改写定义。         |
| 当前创作     | 自动保留的工作台状态，组合文本、资源实例、生成设置及图像编辑状态。         |
| 操作         | 用户要完成的工作，例如生成、局部重绘、放大或 Director 处理。               |
| 任务         | 一次已提交操作的执行与调度单位；批次负责组织多个任务。                     |
| 结果         | 可以继续使用、比较和保存的最终输出，附带必要的生成说明。                   |
| 媒体资产     | 结果、源图、遮罩及参考图的实际内容载体；业务用途不由存储位置决定。         |
| 资源库与集合 | 组织、检索和复用资源、结果及其关系的入口。                                 |

这些概念不逐一对应 crate、服务或数据库表。定义与实例是使用关系，结果与媒体是业务语义与内容载体。历史、图库和资源选择器是不同查看方式，共用结果与媒体事实，不各自建立所有权和来源关系。

## 资源组合

### 定义、实例与解析结果

资源库保存定义，当前创作引用定义并配置实例，提交时解析为本次实际使用的内容。当前创作保留组合关系，任务使用确定的解析结果；资源更新影响后续编辑和解析，不反向修改已经提交的任务。

本次调整应保存在实例中。修改衣着、光照或风格中的一项，不应迫使用户复制整个资源定义。

### 内容与配方

Chunk 提供有明确边界的内容，插入片段不会隐式修改模型、尺寸或采样设置。Preset 组织配方，可以面向基础提示、负面提示、角色提示或图像参考，但各输出的目标必须明确。人物、画风、构图等是资源的用途，不需要分别建立资源系统。

Preset 只声明自己负责的设置，未声明部分继续使用当前创作或模型默认值。它不是整张工作台的快照，也不是覆盖全部字段的配置。

组合优先于多层继承。组合顺序、覆盖来源和本次局部调整需要明确表达，使用户知道某个值为何生效，并能够撤去覆盖。提示词和生成参数采用各自的组合语义，不套用同一种通用 JSON 合并规则。

### 引用、展开与身份

引用资源保留复用关系；展开资源把当前内容转为可直接编辑的文本，两者都是正常工作流。名称和文件夹用于理解与组织，引用依赖稳定身份。浏览、管理和导出围绕同一套身份与依赖关系展开。

公开参数、嵌套组合和依赖打包逐步实现。初版不需要完整模板语言、节点编辑器或资源版本控制平台。

### 模型适配与解释

资源默认尽量复用，必要时提供模型特定变体或适用建议。“内容在哪个模型更合适”属于资源设计；“某字段在该模型是否合法”属于 bridge。nib 不维护第二套模型能力矩阵或 NAI 校验规则。

编辑界面应展示展开后的内容及片段、参数和覆盖的来源。生成记录保存足以解释和复用结果的实际使用信息，不归档整个解析过程。恢复一次提交的内容与完整恢复旧版资源结构是不同能力；后者可由未来的资源版本功能承担，不要求初版保存全部历史定义。

## 创作与执行流程

### 工作台布局

工作台采用扁平、紧凑的桌面软件布局和黑白双主题，青绿用于焦点、选中及主要操作。顶部小品牌后左对齐“创作、导演工具、画廊、资源库、设置”，可直接导航。标题栏不放命名草稿标签、自动保存状态或副标题，保留窗口拖动、双击最大化或还原与窗口控制。[完整工作台视觉参考](images/workbench-reference.png)用于说明基础形态，具体布局和可用操作以当前界面为准。

创作页左侧是生成侧栏，宽度约 340–390px，右侧是主要画布与结果区。侧栏上部从上到下为单行模型选择、正负提示词与紧邻的角色编辑、应用的 Preset、图像与参考和尺寸设置，内容独立滚动。生成参数固定在侧栏底部、生成按钮上方，滚动编辑提示词和材料时仍可调整；Anlas 估算放在生成按钮右侧。空提示词是等待输入的正常状态，不自动请求估费或显示错误。参数与资源问题仍要明确显示，NAI 合法性由 bridge 判断。资源库作为完整页面提供列表、筛选和原件编辑；添加 Chunk 和配方可进入同一资源页选择插入，返回创作后保留编辑上下文。“解析”仍按需打开最终文本、来源、覆盖和依赖问题。

右侧主区在同一位置显示所选请求的等待、预览与最终图片；多样本按等分网格排列，选中后查看单张大图。收到最终样本仍等待完整请求与结果保存，最终图片载入前保留相应预览。下方最近图片默认 20 张，可在设置中选择 1–200；完整图片历史进入画廊，任务按批次在抽屉中查看与操作。源图查看、遮罩和角色位置沿用主区，按上下文切换。图片操作使用紧凑纯图标单排覆层，名称由 tooltip 和可访问标签提供，实际样本种子可复制或填入参数。参数与来源在详情中按需查看，不常驻内部身份。

基础生成参数依次显示 Steps、Guidance，再以双列显示 Seed 与 Sampler；Steps 和 Guidance 提供滑块与数值输入，范围随模型能力变化。整个参数区可手动收起，收起后保留实际步数与 Guidance 的简短摘要。低频采样、输出与执行设置放在同一层默认折叠的高级区，摘要只保留已设置数量或短关键项。折叠不改写值；留空继承，显式关闭和零种子仍有各自语义。字段错误和诊断展开对应区域并可定位，自动调整与严格拒绝由 SDK 执行。独立 Director 处理使用专门 Tab，按工具保留源图、参数、策略与输出选择；恢复工具输入不替换主创作。PNG 文本写入保留按图归属的编辑，并产生关联源图的独立资产；直接基于所选结果的放大、局部重绘等动作留在结果上下文。

质量标签、负面预设、Furry 模式和模型支持的透明背景通过提示词旁的图标打开浮层设置。基础、负面、角色、Chunk、实例覆盖及解析文本共用组件，并采用 Maple Mono 等宽字体。字面文本自动计数，图标浮层显示 Token 数量及错误；实际分词器按模型选择，与显示字体独立。有效提交文本另显示含质量和负面预设后的用量。界面不显示 Token IDs，也不提供标签建议。角色提示采用紧凑可折叠条目，两名及以上角色时，自动、自定义与画布定位入口同排位于角色上方。参考图片采用各自有边界的紧凑卡片，精确参考的 Strength、Fidelity 与信息提取量直接展示；氛围转移强度归一化属于集合设置。

源图和当前操作位于配方之后。图生图与 Max Enhance 共用参数，后者明确输入、输出和计价尺寸；独立放大只展示适用输入。尺寸采用 SDK 预设与自定义宽高的紧凑网格。“请求次数”表示应用批次中的 1–8 次请求；“样本数”表示单次请求产出，范围由 SDK 随模型与尺寸决定，两者分别表达。切换若会替换源图或专有设置，先确认；仅查看图片不改变创作。图片元信息检查与用作底图分别操作，恢复前展示替换范围和缺失材料。

遮罩与源图共用主画布，应用后的遮罩与未应用编辑分别保存。笔画与撤回历史按源图归属，离开时明确选择应用、保留或放弃；保留不会改写当前生成操作。任务只引用已应用的不可变遮罩，画布编辑不反向修改任务。恢复生成内容保留尚未处理的画布编辑；干净画布重新打开时跟随本次恢复的遮罩。

常规控件高约 30px、主要生成按钮约 40px，使用细边框、约 4px 圆角和分组间距组织内容，避免多层卡片。说明只在对应字段旁的统一帮助浮层中按需显示；删除口号和重复说明。帮助支持悬浮、键盘与点击，错误、资源未保存、取消费用风险等决策信息不藏入帮助。自动保存保持静默，失败时保留可见错误和重试。

窄窗口把侧栏与结果区按阅读顺序重排，资源列表在进入详情后提供返回入口；折叠、切换标签和导航保留编辑、搜索与选中上下文。长名称与较多资源允许换行或滚动，不挤压核心操作；浮层限制在视口内并保留关闭、焦点与键盘路径。

### 完整界面与扩展

设计面向完整创作能力，不以阶段性功能清单划定信息结构。新增能力进入已有任务上下文，避免每个后端模块都变成一个导航页。

| 区域           | 内容与扩展方式                                                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 提示词与配方   | 基础、负面与角色作用域各有明确目标；组合行保持启用、编辑和更多操作，排序、覆盖及展开归属当前实例。公开参数或嵌套组合在对应配方内展开，词库补全贴近输入，不另建常驻栏。                                                |
| 图像与参考输入 | 位于配方之后，源图、遮罩、氛围转移、精确参考与角色各有明确分组，常用输入和强度直接展示，低频选项按需展开。可用性与冲突依据 SDK 能力，切换后保留尚可恢复的输入并解释不生效原因。角色提示直接编辑，位置编辑使用主画布。 |
| 参数与提交     | 尺寸留在输入区，步数、引导、种子和采样器固定在侧栏底部，低频采样、输出和执行设置收进单层高级区。参数区可独立收起，费用与提交对象一致；排队、运行、失败和重试在同一任务区表达。                                        |
| 画布与结果     | 查看、比较、图像处理与角色位置共用主区；高频工具随操作切换，低频动作进入菜单。历史与图库使用同一结果事实；不可用媒体显示原因，不进入恢复或再次生成路径。                                                              |
| 资源库         | 搜索、类型与集合筛选、新建和导入导出归入紧凑工具栏；列表负责选择与插入，详情负责原件编辑、依赖和管理。快捷选择服务当前创作，全库管理沿用同一资源身份；结果、参考与在线来源保留各自类型和可写边界。                    |
| 设置           | 账户凭据、外观、生成偏好、存储与缓存、快捷键和扩展配置按稳定主题分组；设置原位编辑，秘密凭据单独输入。只展示已有可用配置，账户订阅或余额未读取时不得伪造状态。                                                        |

所有页面和浮层共享密度、边框、焦点、菜单、帮助和错误表达，集合详情保留必要的显式保存与离开保护。完整设计中的后续能力不代表已经实现；当前能力以 README 为准。

### 参考材料与氛围转移编码

精确参考、氛围转移原图和氛围转移编码是不同的材料用途，依据当前模型能力选择；材料类型不适用时明确提示并保留编辑值，不自动替换或转换。添加、替换、排序、启停参考和调整引用强度属于创作编辑，不隐式发起编码。Preset 可声明参考材料，实例只保存本次覆盖；展开后保留当时有效的材料和设置。

氛围转移文档用于保存和交换材料，可以包含多个条目、原图以及不同模型和参数的编码。导入时保留完整文档，使用时由用户明确选择所需原图或编码；编码缺少原图时仍可复用，但不能据此重建原图或假定能够调整提取参数。材料选择、文档管理与编码提交各有明确入口。

氛围转移原图行提供显式编码按钮、预计费用及状态。点击后优先复用相同材料与有效参数的可用编码，或复用相同输入的未完成任务，需要新编码时才进入付费队列。完成后更新仍保持原输入的那一行；更换或移除该行不会被迟到结果覆盖。编码保留为可复用材料，在参考行与材料选择中使用，不进入图片预览、最近图片或画廊，不另设氛围转移结果标签。

### 操作与状态

工作台隐式维护一份当前创作：提示词、资源实例、生成参数及图像编辑状态的修改自动保存，重新打开时自动恢复。当前创作不命名、不新建或切换保存条目，也不提供常规保存操作；需要命名复用的内容归入 Chunk 或 Preset。自动保存失败时保留当前编辑并提示重试，关闭窗口前等待写入完成。

主流程为：**当前创作与资源实例 → 资源解析 → bridge 请求与准备 → 任务执行 → 最终结果**。

资源解析确定本次内容；bridge 形成并执行有效的 NAI 请求；Jobs 决定何时执行及怎样呈现任务状态；结果能力决定保留什么以及怎样继续使用。

操作类型与返回方式分别表达。流式预览是执行反馈，不是独立创作操作。不同操作可以共用调度和结果呈现，不必共享不适用的请求字段。

实时预览按任务与样本归属，与历史图片分别保留查看上下文；切页不转移帧的归属。只显示实际步骤，不推算完成百分比。取消、失败与中断保留各自任务记录；显式重试建立新任务并继续使用原冻结内容、凭据与执行配置。请求估算、账户采样和请求终态只表达各自事实，不能推断实际扣费。

前端围绕当前创作组织 Prompt、资源、参数、参考输入、画布和结果，不把后端模块逐一映射成页面。资源库作为工作台完整页面直接服务当前创作；切换页面保留原件编辑，未保存修改仍受关闭保护。

高频编辑与显示状态由前端维护，长期数据和执行能力由 Rust 提供。只读查询共用 Query 缓存，当前创作和应用偏好由保存协调器拥有；查询回包不覆盖未保存编辑。流式帧与媒体 Blob URL 分别管理瞬时内容，避免建立重复媒体缓存。实际执行与 NAI 规则仍由 Rust 和 bridge 负责。

## 数据生命周期

| 类别               | 示例                                       | 保留原则                                     |
| ------------------ | ------------------------------------------ | -------------------------------------------- |
| 用户创作数据       | Chunk、Preset、库组织、当前创作与参考材料  | 长期资产，优先支持组织与复用。               |
| 最终结果与必要记录 | 最终图片、实际使用内容与参数、必要来源关系 | 支撑查看、复用及按记录重新提交。             |
| 可重建派生数据     | 缩略图、搜索索引、编译缓存                 | 可清理的缓存，不建立新的资产所有权。         |
| 瞬时执行数据       | 流式中间帧、进度、准备对象、临时解析信息   | 只在执行期间存在，不进入历史或永久事件记录。 |

图像和氛围转移编码分别保留各自确认完成的最终产物。每个图像样本只保留最终版本。用户主动进行的多次生成与修补产生不同最终结果，不属于应丢弃的采样中间帧。

结果记录保存一份足以解释与复用结果的有效信息，不逐层保存编辑请求、领域请求、归一化请求、准备对象和完整协议载荷。执行通知与长期结果保存使用不同路径；普通状态变化可触发查询刷新，高频预览使用瞬时更新，事件系统不成为另一份永久数据来源。

重新获取成本明显的数据，例如氛围转移编码，应按复用价值决定保留策略，不简单归为可随意删除的缓存。

结构化信息默认采用 SQLite，媒体内容采用文件或 Blob 存储，通过所属能力读写。数据库结构、文件位置和索引属于后端实现，不决定产品概念。

应用偏好与账户配置始终全局保存。设置采用账户与连接、生成与预览、外观、存储四个二级导航，右侧使用完整内容宽度。可以管理多个命名账户并选择一个用于后续操作；密钥只存于 Windows 凭据管理器，更换时建立不可变版本，任务保留提交时的版本。有未完成任务引用时拒绝删除账户并指向任务处理，原凭据缺失不改用当前账户。账户自动采样订阅与余额，失败保留同身份上次成功值并标记过期；常规界面不提供刷新按钮，错误时提供重试。

数据目录只决定创作数据库与媒体的位置，nib 不提供可新建、打开或来回切换的工作区。配置目录固定，路径只读显示并可打开所在目录；通过原生目录选择更改数据位置。选择后保存草稿与偏好，阻止新写入和新请求，等待已付费请求保存完整结果，再复制、同步并验证。成功后发布新路径，当前进程保持只读待重启；失败恢复原目录写入。原目录始终保留，未保存资源先由用户处理，不丢弃编辑来完成迁移。开发与正式环境彼此隔离。

## 扩展原则

资源定义与实例、组合解析、编辑会话、bridge 接入、任务与最终结果，以及支撑它们的存储和查询构成应用核心。具体 NAI 操作按需要接入，尚未接入的操作不预建空壳服务。

词库增强、在线发现、Agent、本地分析、复杂批量策略和资源分发作为外围能力接入。Agent 是现有应用能力的另一种调用方式，不另建当前创作、生成器和资源库；新增发现来源扩展查询后端和专有界面，不重建全局资源模型。

提前稳定组合方式、语义归属和数据生命周期，具体接口在首个真实实现中收敛。新增功能应主要增加实现，而不是迫使既有模块经过更多中间层；不为未知需求建立万能插件、工作流或多供应商框架。
