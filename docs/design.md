# nib 设计说明

本文定义产品与架构基线，整理自 2026-10-21 的 nib 设计指导。当前可用能力见 [README](../README.md)，工程实现约束见[开发说明](development.md)。

## 产品定位

nib 是本地优先、专用于 NovelAI 的桌面创作工作台。原生图像操作完成创作，Prompt 资源系统沉淀并复用创作方法；两者共同构成初版产品，Chunk 和 Preset 不作为基础生成器完成后才补充的管理功能。

“轻量”指核心概念明确、同一语义只有一个归属、已有能力直接复用、外围能力逐步接入。应用采用模块化单体，模块通过清晰的公开能力直接协作。模块、文件和 crate 的数量不是架构质量指标；职责不同或确有替换需求时才增加边界。

## 创作对象

| 概念           | 职责                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| Chunk          | 可复用的提示词内容；从纯文本开始，按需要增加少量公开参数。                 |
| Preset         | 组合片段、提示词作用域、参考材料和必要默认参数的创作配方。                 |
| 资源定义       | 资源库中的可复用原件，具有稳定身份、内容与组织信息。                       |
| 资源实例       | 一次使用定义的方式，保存本次参数、启用状态与局部覆盖，不改写定义。         |
| 草稿与编辑会话 | 当前创作，组合文本、资源实例、生成设置及图像编辑状态。                     |
| 操作           | 用户要完成的工作，例如生成、局部重绘、放大或 Director 处理。               |
| 任务           | 一次已提交操作的执行与调度单位；批次负责组织多个任务。                     |
| 结果           | 可以继续使用、比较和保存的最终输出，附带必要的生成说明。                   |
| 媒体资产       | 结果、源图、遮罩及参考图的实际内容载体；业务用途不由存储位置决定。         |
| 资源库与集合   | 组织、检索和复用资源、结果及其关系的入口；项目或工作区可作为可选组织方式。 |

这些概念不逐一对应 crate、服务或数据库表。定义与实例是使用关系，结果与媒体是业务语义与内容载体。历史、图库和资源选择器是不同查看方式，共用结果与媒体事实，不各自建立所有权和来源关系。

## 资源组合

### 定义、实例与解析结果

资源库保存定义，草稿引用定义并配置实例，提交时解析为本次实际使用的内容。草稿保留组合关系，任务使用确定的解析结果；资源更新影响后续编辑和解析，不反向修改已经提交的任务。

本次调整应保存在实例中。修改衣着、光照或风格中的一项，不应迫使用户复制整个资源定义。

### 内容与配方

Chunk 提供有明确边界的内容，插入片段不会隐式修改模型、尺寸或采样设置。Preset 组织配方，可以面向基础提示、负面提示、角色提示或图像参考，但各输出的目标必须明确。人物、画风、构图等是资源的用途，不需要分别建立资源系统。

Preset 只声明自己负责的设置，未声明部分继续使用当前草稿或模型默认值。它不是整张工作台的快照，也不是覆盖全部字段的配置。

组合优先于多层继承。组合顺序、覆盖来源和本次局部调整需要明确表达，使用户知道某个值为何生效，并能够撤去覆盖。提示词和生成参数采用各自的组合语义，不套用同一种通用 JSON 合并规则。

### 引用、展开与身份

引用资源保留复用关系；展开资源把当前内容转为可直接编辑的文本，两者都是正常工作流。名称和文件夹用于理解与组织，引用依赖稳定身份。浏览、管理和导出围绕同一套身份与依赖关系展开。

公开参数、嵌套组合和依赖打包逐步实现。初版不需要完整模板语言、节点编辑器或资源版本控制平台。

### 模型适配与解释

资源默认尽量复用，必要时提供模型特定变体或适用建议。“内容在哪个模型更合适”属于资源设计；“某字段在该模型是否合法”属于 bridge。nib 不维护第二套模型能力矩阵或 NAI 校验规则。

编辑界面应展示展开后的内容及片段、参数和覆盖的来源。生成记录保存足以解释和复用结果的实际使用信息，不归档整个解析过程。恢复一次提交的内容与完整恢复旧版资源结构是不同能力；后者可由未来的资源版本功能承担，不要求初版保存全部历史定义。

## 创作与执行流程

主流程为：**草稿与资源实例 → 资源解析 → bridge 请求与准备 → 任务执行 → 最终结果**。

资源解析确定本次内容；bridge 形成并执行有效的 NAI 请求；Jobs 决定何时执行及怎样呈现任务状态；结果能力决定保留什么以及怎样继续使用。

操作类型与返回方式分别表达。流式预览是执行反馈，不是独立创作操作。不同操作可以共用调度和结果呈现，不必共享不适用的请求字段。

前端围绕当前创作组织 Prompt、资源、参数、参考输入、画布和结果，不把后端模块逐一映射成页面。资源库直接服务当前创作，不要求用户离开工作台才能复用资源。

高频编辑与显示状态由前端维护，长期数据和执行能力由 Rust 提供。查询结果、局部 UI 状态、草稿和任务状态各有归属，同一事实不出现多份可独立修改的来源。前端可提供即时反馈，实际执行与 NAI 规则仍由 Rust 和 bridge 负责。

## 数据生命周期

| 类别               | 示例                                        | 保留原则                                     |
| ------------------ | ------------------------------------------- | -------------------------------------------- |
| 用户创作数据       | Chunk、Preset、库组织、保留的草稿与参考材料 | 长期资产，优先支持组织与复用。               |
| 最终结果与必要记录 | 最终图片、实际使用内容与参数、必要来源关系  | 支撑查看、复用及按记录重新提交。             |
| 可重建派生数据     | 缩略图、搜索索引、编译缓存                  | 可清理的缓存，不建立新的资产所有权。         |
| 瞬时执行数据       | 流式中间帧、进度、准备对象、临时解析信息    | 只在执行期间存在，不进入历史或永久事件记录。 |

每个输出样本只保留确认完成的最终版本。用户主动进行的多次生成与修补产生不同最终结果，不属于应丢弃的采样中间帧。

结果记录保存一份足以解释与复用结果的有效信息，不逐层保存编辑请求、领域请求、归一化请求、准备对象和完整协议载荷。执行通知与长期结果保存使用不同路径；普通状态变化可触发查询刷新，高频预览使用瞬时更新，事件系统不成为另一份永久数据来源。

重新获取成本明显的数据，例如 Vibe 编码，应按复用价值决定保留策略，不简单归为可随意删除的缓存。

结构化信息默认采用 SQLite，媒体内容采用文件或 Blob 存储，通过所属能力读写。数据库结构、文件位置和索引属于后端实现，不决定产品概念。

## 实施方向

首先落实资源定义与实例、组合解析、编辑会话、bridge 接入、任务与最终结果，以及支撑它们的存储和查询。具体 NAI 操作按需要接入，尚未接入的操作不预建空壳服务。

词库增强、在线发现、Agent、本地分析、复杂批量策略和资源分发作为外围能力接入。Agent 是现有应用能力的另一种调用方式，不另建草稿、生成器和资源库；新增发现来源扩展查询后端和专有界面，不重建全局资源模型。

提前稳定组合方式、语义归属和数据生命周期，具体接口在首个真实实现中收敛。新增功能应主要增加实现，而不是迫使既有模块经过更多中间层；不为未知需求建立万能插件、工作流或多供应商框架。
