# nib 路线图

本文规划后续实施顺序，不是当前功能清单或发布承诺。当前能力见 [README](../README.md)，产品概念与边界见[设计说明](design.md)，工程约束见[开发说明](development.md)。

后续工作沿“准备内容与参数 → 生成 → 基于图片修改 → 添加角色与参考 → 工具处理 → 保留与复用”的创作流程推进。每一期同时完成界面、状态保留、实际提交说明和结果复用，不以新增表单或 API 封装作为完成标准。

## 阶段三：bridge 能力接入与图像创作

**依赖：** 阶段二的任务、媒体与结果生命周期。

**目标：** 完整贯通 novelai-bridge 0.7.0 已实现业务能力的桌面创作流程。复用现有应用内核、媒体和顺序队列，补齐界面需要的最小通信与持久化缺口；内核接入、界面开放和真实服务验收分别判断。

### 接入范围

以当前锁定的 bridge 公开实现为范围，不把模型描述中已知但输入尚未实现的能力当作可用操作。模型适用性、参数范围、冲突和归一化结果统一来自 SDK，不在 nib 维护另一套 NAI 能力规则。官网用来参考布局与操作路径；官网新增而 SDK 尚未实现的功能，例如 Pixel Snap，不进入本阶段。

| 能力           | 阶段三接入内容                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 完整生成设置   | 用户指定与自动种子、多样本、质量与 UC 预设、legacy UC、透明背景及 alpha 表示、furry、噪声调度、CFG rescale、variety boost、decrisp、SMEA 及图像与响应格式。 |
| 图像操作       | 源图导入、普通与 Max Enhance 图生图、纯补绘和局部图生图、独立放大，以及各操作专有的输入和参数。                                                             |
| 角色与精确参考 | 独立角色正负提示、启用状态和位置；精确参考的用途、图像、信息提取量、强度与 fidelity。                                                                       |
| Vibe           | 原图与编码引用、逐项强度和编码强度归一化；含遮罩、裁剪与种子的源图编码；官方文件、集合和 PNG 的导入导出与材料复用。                                         |
| Director Tools | 描线、草图、去背景、情绪、清理、保留对话框的清理和着色七项操作，保留全部产出及各自适用的输入与参数。                                                        |
| 执行反馈       | SSE / MessagePack 中间预览、最终样本和终态，沿用已有取消、显式重试与重启中断规则。                                                                          |
| 本地辅助       | 独立与有效提示词的 Token 检视、英日标签建议、图像元信息和载体来源、PNG 文本写入及嵌入 Vibe 材料读取。                                                       |
| 账户与费用     | 订阅、余额及 V5 额度查询，带账户上下文的 SDK 估费，以及请求估算、结果和账户采样的费用观察。                                                                 |

具体模型可用性通过 SDK 查询；例如角色提示与精确参考是不同能力，V5 的角色提示不意味着支持图像参考。V3 使用原图 Vibe，其他支持 Vibe 的模型使用编码路径，不能因材料同为图像参考而混用。

### 布局参考与采用方式

主要参考 Atelier 的实际组件与 [NovelAI 当前图像页面](https://novelai.net/image)。官网 V5 与 V4.5 页面已分别查看：参考输入随模型变化，AI Settings 展开后依次提供 Steps、Guidance、Seed、Sampler，Advanced Settings 初始折叠。官方旧版 Overview 截图只作历史示意，不用来确定当前布局。

Atelier 的参考位置为本地相邻工作区 `atelier/apps/desktop/src/` 下的 `features/generation/GeneratePage.tsx`、`features/generation/components/GenerationWorkbenchLayout.tsx`、`GenerationActionDock.tsx` 和 `features/director/DirectorPage.tsx`。借鉴其纵向输入组织、底部操作区、结果转补绘和独立 Director 页面；其固定三栏和右历史栏不直接照搬，参数与模型规则也不从 Atelier 复制。

拟采用以下整体布局，延续 nib 已有黑白双主题、青绿强调色和紧凑密度：

- 顶部 Tab：**创作 / 导演工具 / 资源库 / 设置**。导演工具 Tab 在 3.6 有完整功能时开放，不提前放空页面。
- 创作页：左侧可滚动生成栏，右侧共用结果查看、遮罩和角色定位的主画布。历史默认沿用底部缩略条，较多结果按需展开浏览；不新增永久占据宽度的第三栏。
- 左栏底部固定提交按钮、费用和必要错误。基础参数默认可见，按从上到下的顺序展示；高级参数默认折叠，不把整个表单挤在底部悬浮面板里。
- 结果工具栏直接提供“用作底图 / 局部重绘 / 放大 / Max Enhance”；“发送到导演工具”携带所选图片切换 Tab。操作入口按 SDK 能力和媒体可用性提供。
- 导演工具页采用输入与参数侧栏、输入/输出比较主区和底部提交区，复用任务与结果能力；窄窗口改为输入/结果切换，不固定左右各一栏。
- 窄窗口先收起历史与辅助详情，再按输入、提交、结果顺序重排。侧栏和画布各自滚动，底部操作区不能挡住字段与错误。

生成栏的目标阅读顺序如下。角色、Vibe 和精确参考各自成组；未添加材料时保持紧凑，有内容时显示数量和摘要，编辑时展开。

| 顺序 | 区域               | 字段与操作                                                                                                                               |
| ---- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 模型与模式         | 模型、furry；V5 Full Medium 等选项从 SDK 模型身份映射展示，不另造等价参数                                                                |
| 2    | 提示词             | 正负提示切换、Chunk 组合、质量预设与 UC 预设、Token 反馈和标签建议                                                                       |
| 3    | 配方               | Preset 顺序、实例覆盖、展开与解析入口                                                                                                    |
| 4    | 图像输入           | 源图、当前操作、遮罩与操作专有参数                                                                                                       |
| 5    | 参考与角色         | Vibe → 精确参考 → 角色提示与位置；各组独立启停与编辑                                                                                     |
| 6    | 图像设置           | 宽高、交换宽高、每次请求的样本数                                                                                                         |
| 7    | 基础生成参数       | Steps → Guidance → Seed（自动/指定/使用所选样本）→ Sampler                                                                               |
| 8    | 高级参数，默认折叠 | Noise Schedule、CFG Rescale、Variety Boost、Decrisp、SMEA、SMEA Dyn、Legacy UC；输出子组提供透明背景、Alpha、图像格式、ZIP/JSON 响应选择 |
| 9    | 固定提交区         | 对应操作名称、费用、账户摘要、校验或提交错误、生成/处理按钮                                                                              |

`useCoords` 随角色定位在 3.4 开放。以上覆盖现有 `GenerationSettings` 的 22 个字段；流式模式和校验策略属于执行选项，放在高级区的执行子组，不算新的创作操作。高级区收起时显示已修改项数及必要摘要；隐藏字段出错时自动展开并定位。折叠不重置值，不自动创建实例覆盖。

### 跨阶段约束与必要补充

现有内核与 IPC 的边界见[开发说明](development.md#bridge-的职责)。以下补充随首次使用它的阶段实现，避免先重构全部内核或制造尚无消费者的接口：

- **模型驱动表单：** 现有能力响应不足以生成全部选项与范围。补充 SDK 描述符中实际需要的枚举、范围、固定值和参考冲突投影；SDK 仍负责校验和归一化。切换模型保留可恢复输入，显示“不生效”的字段与原因；默认值、继承值和显式覆盖必须可区分。
- **编辑状态：** 当前 Draft 只有一个操作，不能直接用 Tab 切换覆盖它。生成内容、独立工具编辑、已应用遮罩与未应用编辑分别归属当前创作的相应工作态，按实际用例扩展保存；不引入命名草稿或工作区切换。选中结果与 Tab 是显示状态，不能反向改写创作。跨页带入图片前处理目标页已有编辑，提交不覆盖原输入或结果。
- **解释与恢复：** 新字段上线同一期扩展解析面板、来源定位、冻结提交详情和恢复说明，不只补编辑器。角色、参考与工具专有材料均可追溯，恢复不依赖原 Chunk/Preset 继续存在。
- **任务与费用：** 所有付费操作复用既有顺序队列、冻结输入、取消、显式重试和重启中断规则。账户显式刷新后使相关估费失效并重新计算；未查询、刷新失败、旧快照和未知费用分别表达。
- **通信与媒体：** Token 与标签补前端调用及生成类型；Vibe 文档增加条目、原图和模型/参数缓存摘要，前端不解析 SDK 文件格式。Vibe 编码入口与专用产物展示同一期交付，不能继续被图片筛选隐藏。

### 实施顺序

#### 3.1 准备完整的一次文生图

**交付：** 完整参数、提示辅助、账户估费和结果说明形成可复用的文生图闭环。

- 按上述顺序调整生成栏，接入模型能力查询和必要描述投影，保留现有配方、自动保存与关闭保护。基础参数常显，高级区默认折叠。
- 开放全部适用于文生图的设置、自动与指定种子、多样本；Preset 默认值、当前覆盖、恢复继承和来源解释同步支持。角色定位设置在 3.4 接续。
- Prompt 就近提供英日标签建议，保留服务端顺序与语言专有排名；处理过期查询、错误、键盘选择和插入位置。接入本地独立 Token 检视，以及有效正负提示的请求级计数，明确字面文本和实际提交文本的区别。
- 设置页提供订阅、余额、V5 额度及采样时间和显式刷新，生成区显示必要摘要；账户变化触发重新估费。估费错误与 SDK 调整诊断定位到对应字段。
- 结果区显示全部样本，详情补完整有效参数、来源与已知实际样本种子；可使用所选样本种子或恢复提交内容。图片下载保存实际内容，避免用截图或复制像素替代文件导出。

**必要后端工作：** 模型能力投影；Token/标签通信类型；请求级 Normalize/Reject 选择及必要保存。严格模式拒绝时显示 SDK 原因，不在前端重新实现校验。

**验收：** 显式 false、零种子、继承与覆盖能保存、估费、提交、查看和恢复；切换模型不会静默丢值。多样本均可查看，未知样本种子不伪装成提交种子。高级字段错误可从收起状态定位；账户刷新后不沿用旧估费。

#### 3.2 从图片进入图生图、增强与放大

**依赖：** 3.1 的参数、模型能力与结果说明。

- 打通文件选择、拖入和已有媒体选择，结果可直接“用作底图”。导入保存内容后再引用，原文件不承担后续可用性。
- 接普通图生图的 Strength、Noise、Color Correct、额外噪声种子和原图选项，按实际操作提供；当前操作与有效输入在侧栏可见。
- 在所选结果和源图上下文开放 Max Enhance 与独立放大。Max Enhance 显示 SDK 提供的输入、预期输出和计价尺寸；独立放大只显示其模型、Blur Sigma 等适用参数，不读取无关 Prompt。
- 导入时可检查 PNG/JPEG/WebP 元信息及载体来源，明确区分“仅用作底图”和“恢复已知生成内容”。恢复前展示将替换的范围及缺失材料，不补造遮罩、参考或角色位置。
- 结果详情显示源图关系，所有输出都保留；允许新结果继续作为底图、参考或工具输入。

**验收：** 外部原文件移走后仍可编辑与重启恢复；损坏或缺失媒体不能提交。普通图生图、Max Enhance、独立放大的表单、估费和冻结输入各自正确，未知放大费用显示未知。元信息恢复不会重复追加自动质量/UC 标签。

**参考：** 官方 [Image2Image](https://docs.novelai.net/en/image/controltools/)、[Enhance](https://docs.novelai.net/en/image/enhance/) 与 [Upscale](https://docs.novelai.net/en/image/upscale/)。界面文案与参数以 SDK 实际操作为准，不将官网 Enhance 的控件直接当成 Max Enhance 契约。

#### 3.3 在同一画布完成局部重绘

**依赖：** 3.2 的媒体导入、源图关系和结果上下文。

- 从所选结果或当前源图进入 Inpaint，主区切为遮罩画布；支持绘制、擦除、笔刷大小、撤回/重做、清除、原图/遮罩预览与应用。
- 支持纯补绘与 SDK 允许的附加局部图生图，显示各自适用的 Strength、Noise 等参数；遮罩与源图尺寸适配由 SDK 处理，显示其诊断。
- 已应用遮罩保存为媒体并随当前创作恢复；未应用笔画独立保留。切结果、替换源图、换操作、切 Tab 或关闭时，提供明确应用、保留或放弃路径，不静默覆盖。
- 提交冻结已应用材料，继续画图不会改变排队任务；最终结果回到同一查看与复用流程。

**验收：** 源图、遮罩、局部条件与噪声种子可恢复；缩放、移动画布后绘制位置仍正确。V3 与后续模型的纯补绘/附加条件差异按 SDK 展示。未应用编辑在切换和关闭后按约定保留，取消或失败不丢原图。

**参考：** Atelier 的结果转补绘路径与官方 [Inpaint](https://docs.novelai.net/en/image/inpaint/)；不复制 Atelier 中按模型字符串排除操作的条件。

#### 3.4 编排角色与精确参考

**依赖：** 3.1 的组合设置和 3.3 的画布工具切换、编辑保留。

- 在侧栏管理角色正负提示、启停、排序、移除、Chunk 引用与展开；主区进入角色定位模式，支持自动/自定义定位及 `useCoords`。
- 定位形式和角色上限读取 SDK；网格与自由定位分别提供适用交互，角色选择与画布标记对应。
- 精确参考支持导入或选取图片、用途、强度、Fidelity、信息提取量与逐项启停。显示当前操作与模型的可用性，以及和 Vibe 的实际冲突。
- Preset 原件、当前实例的角色和精确参考输出同步开放，支持局部覆盖、撤销覆盖、来源解释、问题定位与无损展开；普通 Chunk 仍只提供提示词内容。
- 解析与结果详情展示各角色实际文本、Token 用量、位置和参考材料；恢复不需要旧资源定义。

**验收：** 调整角色顺序不串用局部覆盖；停用、缺失引用、超限和模型切换有明确结果。展开后内容和来源材料不丢失，自动定位与自定义位置不被混淆。角色提示可用不能被误判为支持精确参考。

**参考：** 官方 [多角色 Prompt](https://docs.novelai.net/en/image/multiplecharacters/) 与 [Precise Reference](https://docs.novelai.net/en/image/precisereference/)；文档中的适用范围不替代 SDK 查询。

#### 3.5 将 Vibe 编码、文件与生成连成闭环

**依赖：** 3.2 的媒体选择与 3.3 的遮罩；复用 3.4 的参考组、Preset 输出和冲突展示方式。

- 区分 V3 原图参考与 V4/V4.5 编码参考，支持逐项启停、强度和强度归一化；接入 Preset 输出、覆盖、展开和来源说明。
- 在参考组内提供显式“编码 Vibe”：源图、信息提取量、可选遮罩、裁剪及双种子。编码与生成分别估费、分别提交，改变需要重新编码的输入时清楚提示。
- 编码结果以材料卡片展示模型/参数身份和来源，可直接添加为参考、重新选择或导出；已有编码复用不触发隐式编码。缺少原图的编码材料不能提供重新调整提取量的假入口。
- 支持官方单文件与集合导入导出、由原图或编码创建文档、组包、PNG 文档嵌入与读取、已有图片中的嵌入编码提取。
- 增加文档检查视图，列出条目、原图和各模型/参数缓存；用户选定后才派生应用资产，完整文档及未选缓存继续保存。导入到当前参考时明确选择追加或替换。

**验收：** 一次编码后能跨重启复用与导出再导入，不重复计费编码；所有缓存身份保留。Vibe 产物不进入图片渲染路径，也不被结果筛选隐藏；损坏文件、错误模型路径、缺失缓存及参考冲突均可解释。

**参考：** 官方 [Vibe Transfer](https://docs.novelai.net/en/image/vibetransfer/) 的多项设置、缓存复用和文件交换流程。

#### 3.6 在独立导演工具 Tab 处理图片

**依赖：** 3.2 的媒体、结果动作和专有参数表单；可在 3.3–3.5 之外并行推进。

- 开放导演工具 Tab，接描线、草图、去背景、情绪、清理、保留对白清理、着色七项操作。按工具显示 Prompt、Defry 等实际字段；清理的两种语义必须可选择。
- 输入可来自导入、媒体选择或结果“发送到导演工具”；保留生成内容与工具工作态，切换工具保留各自编辑值。新图片带入不能无提示覆盖未处理编辑。
- 显示输入/输出比较、估费、提交与任务状态；保留全部输出并允许继续处理、发送回创作、用作参考或保存文件。去背景的多种产出分别可选。
- 放大、Max Enhance 和 Inpaint 继续留在结果或源图上下文，不要求绕行导演工具 Tab。
- 在媒体详情的高级菜单提供 PNG 文本检查与写入；写入生成关联原图的衍生资产，保留像素与原始资产，输出可下载。嵌入 Vibe 的动作复用 3.5。

**必要后端工作：** 为独立工具编辑增加最小持久化表示与关闭保护，仍通过已有 quote/submit 和队列执行，不新建工具专用执行器。

**验收：** 七项均能从导入图或已有结果进入，专有参数、费用、所有输出和恢复路径正确；切 Tab 不改变主生成内容。PNG 文本写入后可再次检查、导出与复用。

**参考：** Atelier 独立 Director 页面及官网 [Director Tools](https://docs.novelai.net/en/image/directortools/)；官网当前额外提供的 Pixel Snap 不进入 SDK 接入清单。

#### 3.7 接入执行反馈并完成全流程验收

**依赖：** 流式部分在 3.1 后即可并行，最终验收在前述流程交付后完成。

- 高级执行选项支持普通返回、SSE 和 MessagePack；使用窗口级唯一订阅，按任务与样本归属显示预览、最终图接收和完成状态。切 Tab 或结果不会把别的任务帧显示到当前结果。
- 预览为瞬时内容，最终图接收不等于任务已完成；等待 SDK 确认完整终态与持久化结果。断流、缺少最终样本、服务端错误和取消均保持真实状态。
- 补齐估算、账户采样和请求终态费用观察的用户摘要；必要时投影 SDK 观察信息，但不复制完整账户响应、不推断实际逐次扣费。解除订阅、过期异步响应和 Blob URL 均有生命周期归属。
- 在设置的高级执行偏好中接入 SDK 已有 JSON/Multipart 请求编码与可选服务端图像缓存，保持默认行为；配置由宿主装配并在客户端重建时正确生效。自定义 Transport、响应解码和协议校验继续由 SDK/宿主承担，不为库级接口增加调试页面。
- 按模型覆盖 V3、V4/V4.5、V5 Full/Medium/Curated 的实际适用路径，逐项验证导入、编辑、估费、提交、结果、取消、重试、重启和再次使用；真实计费样例按已授权范围执行。

**验收：** 不完整流不生成成功记录，中间帧不进入历史；取消后队列可继续，重启不自动重发。图片、Vibe、工具产物均有可达界面路径；配置变化不污染既有冻结任务，凭据变化清除旧账户上下文。

### 依赖、分工与交付门槛

主顺序为 **3.1 → 3.2 → 3.3 → 3.4 → 3.5**；3.6 在 3.2 后可独立开发，3.7 的订阅和预览在 3.1 后可独立开发，最终验收收口全部阶段。提示辅助可作为 3.1 内独立任务推进，不阻塞布局与参数编辑。

使用子代理时先由主代理确定共享通信类型、编辑状态与保存边界，再分配参数/提示辅助、画布/媒体、参考/Vibe、Director、流式反馈等边界明确的工作。共享 Draft、类型生成和顶层布局由单一写入方负责；其他代理消费已确定接口。每期由独立只读子代理核对入口、调用、状态和恢复，主代理复核实际产物，不以子代理完成声明代替验收。

每一期必须同时满足：

- 有实际界面入口，表单、有效值、费用、冻结提交、产物与再次使用形成闭环；不存在模拟成功、空服务或只有封装的交付。
- 相关参数、角色、参考和工具输入随当前创作正确保留；修改源资源不改变已提交任务。切页、切图、失败、取消和关闭不会静默丢弃编辑。
- 自动检查遵循[开发说明](development.md)：运行受影响的纯逻辑单元测试及约定检查，通信变更执行 `pnpm types`，统一收口使用 `pnpm check`，桌面构建独立运行 `pnpm build:desktop`。文档变更只做对应 Markdown 检查，不无关扩大代码验证。
- 人工核对交互、键盘路径、窄窗口、媒体可用性、SQLite 重启恢复及真实 NovelAI 服务；静态检查和纯内存测试不能代替这些验收，未执行项明确保留为未验收。
- README 只更新已实际开放的能力，稳定交互与边界分别归入设计/开发说明；本文件移除已完成安排，不追加本轮验证日志或复制详细现状。

## 阶段四：资源组织与可携带性

**依赖：** 已有实际积累的资源、当前创作与结果；基础浏览和查找已在前两阶段实现。

**目标：** 创作积累能持续整理、查找、迁移和复用。

- 增加集合、关系筛选与面向真实使用需求的查询，让资源库、历史和图库使用同一套资源与媒体事实。
- 实现资源及依赖的导入导出；明确同一身份冲突、缺失依赖和媒体引用的处理，不依赖名称或文件路径判断身份。
- 对确有需求的配方增加少量公开参数和嵌套组合，保留有序覆盖、来源解释及直接展开路径。
- 按实际数据量完善缩略图和索引的重建，以及媒体与记录一致性的诊断。删除或清理不得误删仍被创作数据引用的内容。

**验收：** 配方与依赖可在新的本地库中恢复使用；冲突和缺失有明确结果；改名和调整组织不破坏引用；缓存清理不损失原始创作数据，恢复某次生成内容不依赖旧版资源定义仍然存在。
