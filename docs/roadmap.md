# nib 路线图

本文规划从工程骨架到可用创作工作台的后续实施顺序，不是当前功能清单或发布承诺。当前能力见 [README](../README.md)，产品概念与边界见[设计说明](design.md)，工程约束见[开发说明](development.md)。

优先完成“资源复用 → 当前创作 → 提交操作 → 保留结果 → 再次使用”的闭环。阶段一与阶段二共同构成首个可用版本；不会在只接通生成 API 后把资源系统推迟为外围功能。

## 阶段三：bridge 能力接入与图像创作

**依赖：** 阶段二的任务、媒体与结果生命周期。

**目标：** 尽量贯通当前 bridge 已实现能力的应用用例、持久化和 IPC，使用户能够基于已有图片、角色与参考材料继续创作。内核接入与界面开放分别验收，界面按创作流程分步完成；尚无界面入口的能力不列为当前用户功能。

### 接入范围

以当前依赖的 bridge 公开实现为范围，不把模型描述中已知但输入尚未实现的能力当作可用操作。模型适用性、参数范围、冲突和归一化结果统一来自 SDK，不在 nib 维护另一套 NAI 能力规则。

| 能力           | 阶段三接入内容                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 完整生成设置   | 用户指定与自动种子、多样本、质量与 UC 预设、legacy UC、透明背景及 alpha 表示、furry、噪声调度、CFG rescale、variety boost、decrisp、SMEA 及图像与响应格式。 |
| 图像操作       | 源图导入、普通与 Max Enhance 图生图、纯补绘和局部图生图、独立放大，以及各操作专有的输入和参数。                                                             |
| 角色与精确参考 | 独立角色正负提示、启用状态和位置；精确参考的用途、图像、信息提取量、强度与 fidelity。                                                                       |
| Vibe           | 原图与编码引用、逐项强度和编码强度归一化；含遮罩、裁剪与种子的源图编码；官方文件、集合和 PNG 的导入导出与材料复用。                                         |
| Director Tools | 描线、草图、去背景、情绪、清理、保留对话框的清理和着色七项操作，保留全部产出及各自适用的输入与参数。                                                        |
| 执行反馈       | SSE / MessagePack 中间预览、最终样本和终态，沿用已有取消、显式重试与重启中断规则。                                                                          |
| 本地辅助       | 独立与有效提示词的 Token 检视、英日标签建议、图像元信息和载体来源、PNG 文本写入及嵌入 Vibe 材料读取。                                                       |
| 账户与费用     | 订阅、余额及 V5 额度查询，带账户上下文的 SDK 估费，以及请求估算、结果和账户采样的费用观察。                                                                 |

具体模型可用性通过 SDK 查询；例如角色提示与精确参考是不同能力，V5 的角色提示不意味着支持图像参考。V3 使用原图 Vibe，其他支持 Vibe 的模型使用编码路径，不能因材料同为图像参考而混用。

### 后续实施顺序

现有内核与 IPC 的边界见[开发说明](development.md#bridge-的职责)。后续工作集中于桌面入口和真实流程验收；发现内核缺口时在对应真实用例中修正，不增加占位服务。

#### 3.1 基础图像创作界面

- 在当前工作台开放源图导入、结果转为输入与图生图，显示所选操作及其实际有效参数。
- 增加遮罩绘制、应用与恢复，将局部重绘接入同一画布。切换结果或操作前处理未应用编辑，不静默覆盖；当前创作自动保留源图与遮罩选择。
- 结果详情展示必要来源关系，缺失或损坏材料不能当作可用输入；导入不依赖外部原文件继续存在。

#### 3.2 角色、参考与完整参数界面

- 开放完整生成设置与多样本控制，显示 SDK 的能力查询、归一化诊断和实际提交值。模型切换保留可恢复输入，并解释不生效原因。
- 在侧栏编辑独立角色正负提示，在画布定位角色；精确参考和 Vibe 各有适用的输入与参数。
- 提供显式 Vibe 编码和已有材料复用入口，提交前分别说明编码与生成费用，避免重复付费编码。
- 在 Preset 编辑与实例中开放角色和参考输出，提供局部覆盖、撤销覆盖、来源解释与展开；普通 Chunk 继续只提供提示词内容。

#### 3.3 图像工具与执行反馈界面

- 七项 Director、独立放大与 Max Enhance 进入对应图像上下文，保留操作专有参数，生成图像与 Vibe 材料分别展示。
- 导入图片时读取可识别的生成信息和嵌入 Vibe，提供已知字段复用并说明缺失项，不补造参考、遮罩或角色位置。
- 开放英日标签建议和独立 Token 检视，展示有效提示词和各角色的 Token 用量；提供显式账户刷新、快照时间与费用反馈，保留未知估价；估算和账户采样不能当作逐次实际扣费凭证。
- 接入瞬时预览与取消反馈；中间帧不进入历史，不完整流不能显示为完成。窗口负责释放订阅和图像展示资源。

#### 3.4 真实流程验收

- 核对既有文生图闭环以及新增操作的真实服务、费用和取消表现，按需要安排明确的计费样例。
- 验证媒体导入、当前创作保存、结果来源、重启恢复和缺失材料处理；构建与纯内存测试不能替代这些验收。

界面沿已有工作台分步开放，不为每项 SDK 能力新增导航页。各轮分别验收，README 只描述实际可用入口，不把 IPC 已接通写成完整桌面能力。

### 验收

- **内核：** 范围内各项能力均有真实应用入口和 IPC，可完成必要的输入保存、解析或估费、提交、执行与产物读取；需要重试和恢复的操作使用冻结材料，不存在空服务或模拟成功响应。
- **生命周期：** 源图、遮罩和参考材料可随当前创作恢复；来源关系明确，缺失材料返回可解释错误。生成、Director 与 Vibe 产物各有适用表示，流式中间帧不进入长期记录，不完整流不产生任务成功状态。
- **桌面：** 从结果或导入图片进入操作并得到新的最终结果；引用、覆盖、展开和恢复在新增作用域下仍成立。按各轮界面实际开放情况分别验收，不用内核检查代替桌面创作验收。
- **验证：** 自动检查遵循开发说明，纯逻辑单元测试覆盖新增的组合、冻结、状态和恢复行为；真实 NovelAI 服务、费用及人工创作流程单独安排验证，不以静态检查或本地测试代替。

## 阶段四：资源组织与可携带性

**依赖：** 已有实际积累的资源、当前创作与结果；基础浏览和查找已在前两阶段实现。

**目标：** 创作积累能持续整理、查找、迁移和复用。

- 增加集合、关系筛选与面向真实使用需求的查询，让资源库、历史和图库使用同一套资源与媒体事实。
- 实现资源及依赖的导入导出；明确同一身份冲突、缺失依赖和媒体引用的处理，不依赖名称或文件路径判断身份。
- 对确有需求的配方增加少量公开参数和嵌套组合，保留有序覆盖、来源解释及直接展开路径。
- 按实际数据量完善缩略图和索引的重建，以及媒体与记录一致性的诊断。删除或清理不得误删仍被创作数据引用的内容。

**验收：** 配方与依赖可在新的本地库中恢复使用；冲突和缺失有明确结果；改名和调整组织不破坏引用；缓存清理不损失原始创作数据，恢复某次生成内容不依赖旧版资源定义仍然存在。

## 外围扩展：按实际需求排期

以下方向分别进入对应能力，不预设共同发布批次，也不作为首个创作闭环的前置条件。

| 方向                   | 接入条件与边界                                                              |
| ---------------------- | --------------------------------------------------------------------------- |
| bridge 尚缺的 NAI 操作 | 根据真实需求先补齐 SDK，再接入应用；已提供能力的接入范围见阶段三。          |
| 词库增强               | Prompt 编辑已有稳定入口后增加补全与查询后端，保留来源信息。                 |
| 在线作品发现           | 在所属查询能力组合远程来源，使用适合该来源的界面，不重建全局资源模型。      |
| 批次与调度策略         | 在 SDK 单次多样本之外按重复创作需求组织多个任务，不升级为可编程工作流平台。 |
| Agent 与本地分析       | 调用现有应用能力，不另建当前创作、任务或资源库；明确执行权限和结果归属。    |
| 资源分发与历史版本     | 根据实际共享和恢复需求决定，不以首版完整资源版本平台为目标。                |
| 其他平台与正式分发     | Windows 闭环稳定后补对应平台构建与验收，再安排安装包、签名和更新机制。      |

## 推进与维护

阶段三接续桌面图像创作入口，并核对既有文生图和新增操作的真实服务、费用验收证据；必要缺口在对应领域修正。具体交互随各轮真实流程收敛，不预设空接口。

每次进入新阶段，核对已有实现和前一阶段验收结果；完成项从路线图移除，当前行为更新到适当说明中。范围或顺序变化只在本文件维护，不另建重复的阶段状态清单。自动检查遵循开发说明的边界，构建成功不能代替实际创作流程的验收。
