# nib 路线图

本文规划后续实施顺序，不是当前功能清单或发布承诺。当前能力见 [README](../README.md)，产品概念与边界见[设计说明](design.md)，工程约束见[开发说明](development.md)。

后续工作沿“准备内容与参数 → 生成 → 基于图片修改 → 添加角色与参考 → 工具处理 → 保留与复用”的创作流程推进。每一期同时完成界面、状态保留、实际提交说明和结果复用，不以新增表单或 API 封装作为完成标准。

## 阶段三：真实服务验收收口

桌面业务入口已接通，当前能力与使用方法见 [README](../README.md#生成与结果复用)。真实 NovelAI 服务验收仍有以下必要缺口，完成前不将阶段三标为结束：

- 在原生窗口直接观察可区分的流式中间预览帧；占位、最终样本和保存状态不能代替这项观察。
- 使用不同真实账户核对凭据切换与已排队请求的账户绑定，并验证付费请求执行期间迁移数据后的产物保留与恢复。
- 补验背景移除、保留对白清理的真实产物及复用，执行前明确费用额度。

以真实服务产物、持久化与重启后的恢复结果收口；服务失败、未知费用和未执行路径明确保留，不能因构建通过而视为验收完成。官网新增但 SDK 尚未实现的操作不在本阶段范围内。

## 阶段四：资源组织与可携带性

**依赖：** 已有实际积累的资源、当前创作与结果；基础浏览和查找已在前两阶段实现。

**目标：** 创作积累能持续整理、查找、迁移和复用。

- 增加集合、关系筛选与面向真实使用需求的查询，让资源库、历史和图库使用同一套资源与媒体事实。
- 实现资源及依赖的导入导出；明确同一身份冲突、缺失依赖和媒体引用的处理，不依赖名称或文件路径判断身份。
- 对确有需求的配方增加少量公开参数和嵌套组合，保留有序覆盖、来源解释及直接展开路径。
- 按实际数据量完善缩略图和索引的重建，以及媒体与记录一致性的诊断。删除或清理不得误删仍被创作数据引用的内容。

**验收：** 配方与依赖可在新的本地库中恢复使用；冲突和缺失有明确结果；改名和调整组织不破坏引用；缓存清理不损失原始创作数据，恢复某次生成内容不依赖旧版资源定义仍然存在。

## 词库与资源分发验收

词库查询、可选资源安装、共享编辑器联想、画师选择与资源构建入口已接入；实际用法见 README，工程边界和工作流见开发说明。剩余验证集中于以下范围，完成前不将资源分发视为已交付验收：

- 完成统一静态检查、纯逻辑单元与 Windows 桌面构建，并核对原生 ONNX Runtime 随产物提供。
- 在原生窗口核对基础 / 语义安装、取消、失败与旧资源保留，确认独立资源目录和 `NIB_DEVELOPMENT_HOME` 隔离。
- 人工核对各提示词入口的联想、IME、旧光标 / 编辑 / 模型 / 资源返回结果拒绝、单次撤销、只读查询，以及画师多选权重、英文 / 假名与 Chunk / Preset 复用。
- 运行完整真实来源资源构建，核对模型契约、增量编码复用、压缩 tokenizer、冷启动离线查询及增强关联数据。
- 在远程 runner 执行拆分 CI、无来源变化跳过与资源候选构建；手动发布可信候选并核对失败重试、不可变资产和 `lexicon-current` 指针更新。

## 外围扩展：按实际需求排期

以下方向分别进入对应能力，不预设共同发布批次，也不作为首个创作闭环的前置条件。

| 方向                   | 接入条件与边界                                                              |
| ---------------------- | --------------------------------------------------------------------------- |
| bridge 尚缺的 NAI 操作 | 根据真实需求先补齐 SDK，再接入应用；已接入能力见 README。                   |
| 在线作品发现           | 在所属查询能力组合远程来源，使用适合该来源的界面，不重建全局资源模型。      |
| Agent 与本地分析       | 调用现有应用能力，不另建当前创作、任务或资源库；明确执行权限和结果归属。    |
| 资源分发与历史版本     | 根据实际共享和恢复需求决定，不以首版完整资源版本平台为目标。                |
| 其他平台与正式分发     | Windows 闭环稳定后补对应平台构建与验收，再安排安装包、签名和更新机制。      |

## 推进与维护

阶段三收口真实服务与费用验收，之后按资源积累推进阶段四；必要缺口在对应领域修正。具体交互随真实流程收敛，不预设空接口。

每次进入新阶段，核对已有实现和前一阶段验收结果；完成项从路线图移除，当前行为更新到适当说明中。范围或顺序变化只在本文件维护，不另建重复的阶段状态清单。自动检查遵循开发说明的边界，构建成功不能代替实际创作流程的验收。
