# nib

nib 是本地优先、专用于 NovelAI 的桌面创作工作台。原生图像操作与可组合的 Prompt 资源系统共同构成产品核心：用 Chunk 积累提示词片段，用 Preset 组合创作配方，工作台自动保留当前创作。

生成内核直接复用 [novelai-bridge](https://github.com/RhNu/novelai-bridge)，应用采用 Rust 模块化单体、Tauri 和 React / TypeScript。

## 当前能力

已实现资源与当前创作的本地工作台：创建和查找纯文本 Chunk，以 Preset 组合基础提示、负面提示及显式默认设置，在当前创作中使用资源引用、实例覆盖和独立展开内容。解析面板显示实际文本、来源、设置覆盖与缺失依赖；资源和当前创作通过真实 IPC 保存到 SQLite。配置 NovelAI API Key 后可以估算费用、提交文生图、查看顺序任务与最终结果，并将结果内容恢复到当前创作。

界面采用紧凑的黑白双主题和青绿主题色，资源库按需打开，主工作区用于组合编辑、生成与结果复用。图像编辑和参考输入尚未实现。启动应用不需要 NovelAI 凭据，只有显式提交或重试才会发起生成请求。[设计说明](docs/design.md)中的完整产品目标不代表当前功能均已可用。

## 启动

当前开发与构建目标为 Windows x64。准备以下环境：

- Visual Studio 的 C++ 桌面开发工具及 Windows SDK。
- Microsoft Edge WebView2 Runtime。
- Rustup；仓库固定 Rust 1.99.0，包含 rustfmt 和 Clippy。
- Node.js 24.21.0、pnpm 12.14.0，分别由 `.node-version` 和 `packageManager` 声明。

平台依赖安装见 [Tauri 官方前置条件](https://v2.tauri.app/start/prerequisites/)。在仓库根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

预期出现带原生标题栏的 nib 工作台，首次打开时进入空白工作台。开发服务固定使用 `127.0.0.1:1420`；端口占用时会报错，不会静默切换端口。

仅查看浏览器前端可运行 `pnpm dev:web`。浏览器模式会明确提示缺少桌面宿主，不能用于确认 IPC 已连通。

## 本地创作

在“资源库”中新建 Chunk，填写名称和文本并保存；新建 Preset 时，可以为两个提示词作用域分别组合文本和 Chunk，只填写配方负责的默认设置。资源名称允许重复，引用使用稳定身份。

在当前创作中添加文本、Chunk 或 Preset，可以启用、停用和调整顺序。编辑引用内容只建立当前实例的覆盖；撤销覆盖后继续使用原资源。展开 Chunk 会得到独立文本；展开 Preset 会保留当前内容、启用状态和它声明的默认设置，解除资源引用。解析按配方顺序组合内容，再追加当前创作的直接片段，片段间以换行分隔，保留原有提示词语法。

修改提示词、资源实例或生成参数后，工作台会自动保存当前创作；关闭窗口前等待写入，失败时保留编辑并提示重试。重新打开工作台会恢复这份状态。命名复用通过 Chunk 和 Preset 完成，资源定义编辑需要单独保存，未保存时离开会要求处理修改。结构化数据位于桌面应用数据目录的 `nib.sqlite3`。删除资源会保留已有引用并显示缺失问题。

## 生成与结果复用

通过“配置账户”输入 NovelAI API Key，宿主将其保存在 Windows 凭据管理器中；可以在同一入口替换或移除。凭据不会写入前端本地存储、SQLite、日志或结果记录。保存凭据不验证远程账户，也不产生生成费用。

当前创作通过 SDK 本地校验和估费后，点击“生成”将确定的内容加入顺序队列。费用提示未读取账户订阅与余额，是估算而非实际扣费承诺。提交后的文本、参数、随机种子及必要来源固定，继续修改资源或当前创作不会改变已提交任务。

任务区显示排队、执行、完成、失败、取消和中断状态。可以取消任务；运行中的请求可能已被服务端处理，取消不保证免扣费。失败、取消或中断后，只有显式重试才重新提交原来的内容。重新打开应用不会自动续发未完成的请求。

最终图片存于应用数据目录的 `media`，结果记录存于 SQLite。结果区可以查看图片与实际使用内容；确认恢复后，以独立文本和有效设置替换当前创作，再次生成无需原资源仍然存在。缺失或截断的图片会标为不可用，不能当作完整结果打开或恢复。当前不接入流式预览，仅保留完成的最终图片。

## 开发入口

```sh
pnpm build:web
pnpm build:desktop
```

桌面构建生成 Windows 可执行程序，不生成安装包或更新包。完整检查使用 `pnpm check`，还需本机具备 Rusteward 的 `cargo-dev` 和 rumdl；安装、类型生成及命令职责见[开发说明](docs/development.md)。
